## Purpose

## Vision Statement

Menjadi fondasi engineering Laravel yang predictable, modular, terdokumentasi,
dan AI-friendly, sehingga project baru dapat dibuat dengan kualitas serta
konvensi yang konsisten tanpa mengulang keputusan teknis dari awal.

## Mission

- Menyediakan baseline Laravel yang dapat digunakan lintas project.
- Mengubah konvensi arsitektur menjadi contract dan generator yang executable.
- Mempercepat pembuatan module tanpa mengorbankan boundary dan testability.
- Menjadikan dokumentasi sebagai source of truth untuk manusia dan AI.
- Menyediakan jalur upgrade, deployment, dan maintenance yang dapat diulang.
- Menjaga core tetap stabil dan membuka extension melalui contract resmi.

## Problem Statement

- Project Laravel baru sering mengulang setup, dependency decision, dan struktur.
- Pembuatan module manual menghasilkan variasi naming, boundary, dan test.
- Pengetahuan arsitektur sering berada pada pembuat project, bukan dokumentasi.
- AI coding assistant dapat menghasilkan pola berbeda bila context tidak eksplisit.
- Perubahan baseline sulit diterapkan lintas project tanpa versioning dan ADR.

## Product Principles

1. **Reusable by default:** keputusan harus dapat diterapkan lintas project.
2. **Convention before configuration:** konfigurasi hanya untuk variasi yang sah.
3. **Domain boundary first:** module mengikuti domain dan contract, bukan folder teknis semata.
4. **Generated output is reviewable:** source hasil generator harus jelas dan dapat diedit.
5. **Explicit over implicit:** dependency, lifecycle, event, dan ownership terdokumentasi.
6. **AI-readable:** nama, struktur, metadata, dan acceptance criteria konsisten.
7. **Small verified slices:** perluasan dilakukan setelah vertical slice berhasil.
8. **No silent replacement:** perubahan keputusan dilakukan melalui ADR dan migration path.

## Business Goals

| ID | Goal | Indikator |
|---|---|---|
| VG-001 | Mempercepat bootstrap project baru | Quickstart berhasil pada mesin bersih |
| VG-002 | Menstandarkan module | Module generated lulus contract dan structure test |
| VG-003 | Meningkatkan AI-assisted development | AI dapat mengikuti context dan task plan tanpa instruksi lisan |
| VG-004 | Mengurangi architecture drift | Dependency policy, manifest, dan ADR dapat diaudit |
| VG-005 | Meningkatkan delivery confidence | CI, release, rollback, dan operations dapat diulang |

## Baseline Vision Slice

Visi pertama diwujudkan melalui:

- starter kit Laravel 13 React yang terverifikasi;
- Ziggy sebagai route integration;
- penghapusan Wayfinder dan Laravel Boost;
- DDD-lite Modular Monolith dengan domain, contract, dan event;
- generator module dan module console;
- `AccessControl`, `UserManagement`, `AuditLog`, dan `SystemSetting` sebagai module awal;
- dokumentasi `00–07` sebagai executable project context.

Fitur Auth, notification, profile, dan settings bawaan starter kit tetap menjadi
fondasi dan tidak diganti pada baseline awal.

## Success Criteria

Vision dianggap tervalidasi apabila:

- developer baru dapat membuat project dan module pertama dari dokumentasi;
- AI coding assistant dapat menemukan rule, contract, dan acceptance criteria;
- generator menghasilkan output deterministic, conflict-safe, dan testable;
- module awal memiliki boundary, event, contract, dan test yang jelas;
- project dapat di-setup, di-test, di-deploy, dan di-rollback secara terdokumentasi;
- tidak ada Wayfinder atau Laravel Boost pada dependency maupun source code.

## Target Users

1. Owner/architect yang membuat baseline dan mengambil keputusan.
2. AI coding assistant yang menjalankan task berbasis context dan spec.
3. Developer yang membuat module dan feature pada project turunan.
4. QA yang memverifikasi acceptance criteria dan generated output.
5. DevOps yang menjalankan environment, CI/CD, release, dan operasi.

## Stakeholders

| Role | Responsibility |
|---|---|
| Product/Technical Owner | Menetapkan prioritas, scope, dan keputusan produk |
| Software Architect | Menjaga boundary, contract, dan ADR |
| Developer | Mengimplementasikan generator, kernel, dan module |
| QA Engineer | Menetapkan verification dan release gate |
| DevOps Engineer | Menetapkan environment, delivery, observability, dan recovery |
| AI Coding Assistant | Mengikuti context, spec, task plan, dan verification |

## Long-Term Direction

Setelah baseline pertama stabil, starter kit dapat berkembang ke extension system,
package distribution internal, generator feature/CRUD yang terbatas, module
versioning, upgrade tooling, dan framework/kernel runtime yang lebih lengkap.
Semua perluasan harus mempertahankan vision, scope authority, dan verification
gate pada dokumen `00–05`.

## Non-Goals

- Menjadi pengganti Laravel atau framework HTTP baru.
- Menjadi produk SaaS atau aplikasi bisnis spesifik.
- Mengabstraksi semua kemungkinan arsitektur dan database.
- Menghasilkan code tanpa review, test, atau acceptance criteria.
