## Confirmed Architecture Decisions

| Area | Decision |
|---|---|
| Application modules | `app/Modules/System/{Submodule}` |
| Framework distribution | Satu package awal: `packages/StarterKit` |
| Module console | Colon command sebagai format utama: `module:make` |
| Metadata | `module.json` sebagai metadata deklaratif |
| Runtime config | `module.php` hanya untuk runtime configuration |
| Generator conflict | Fail-safe; overwrite hanya dengan `--force` |
| Generator output | Struktur module lengkap tanpa CRUD/API generik otomatis |
| Event strategy | Domain event internal; integration event lintas boundary bila perlu |
| Audit log | Append-only record dengan filtered metadata dan retention policy |
| Distribution | Internal Git repository/package dengan versioned upgrade path |
| Invalid module | Isolated block; module invalid dinonaktifkan, module lain tetap berjalan |
| Permission model | Allow permission dan policy rule; tidak ada explicit deny model |
| Audit retention | Minimal 1 tahun, lalu dievaluasi project turunan |

## How Might We

Bagaimana membuat Laravel starter kit yang dapat dipakai ulang lintas project,
sehingga developer dan AI dapat membuat module baru secara konsisten tanpa
pengetahuan lisan dari pembuat framework?

## Candidate Directions

1. **Template-only starter:** menyediakan folder dan konfigurasi siap salin.
2. **Generator-first starter:** menyediakan command console sebagai jalur utama
   pembuatan module, submodule, contract, test, dan dokumentasi.
3. **Framework platform:** menyediakan kernel, registry, discovery, lifecycle,
   extension, package policy, dan generator sebagai platform extensible.
4. **Convention plus AI context:** menggabungkan generator dengan dokumen,
   rules, manifest, dan output yang mudah dipahami AI.

## Evaluation

| Direction | User value | Feasibility | Reuse |
|---|---|---|---|
| Template-only | Medium | High | Medium |
| Generator-first | High | Medium | High |
| Framework platform | High | Low for first milestone | Very high |
| Convention plus AI context | Very high | Medium | Very high |

## Recommended Direction

Gunakan **generator-first starter** dengan fondasi **convention plus AI
context**. Framework platform tetap menjadi arah jangka panjang, tetapi milestone
pertama hanya membangun kontrak kernel dan generator yang dapat diverifikasi.

## First Vertical Slice

1. Verifikasi Laravel React starter kit.
2. Hapus Wayfinder dan Laravel Boost; pasang dan verifikasi Ziggy.
3. Tetapkan module manifest dan folder DDD-lite.
4. Implementasikan `module:make` dan module console.
5. Generate `AccessControl`, `UserManagement`, `AuditLog`, dan `SystemSetting`.
6. Tambahkan test, dokumentasi output, dan deployment verification.

## Key Assumptions

- Auth, notification, profile, dan settings dari starter kit tetap digunakan.
- Generator menghasilkan struktur deterministik dan dapat dijalankan ulang
  dengan aturan konflik yang jelas.
- Module memiliki boundary dan kontrak yang dapat diuji secara independen.
- `System` menjadi module induk untuk `AccessControl`, `UserManagement`,
  `AuditLog`, dan `SystemSetting`.
- Starter kit dibagikan melalui internal Git repository/package, bukan public
  Composer release pada milestone pertama.

## Not Doing Yet

- Generator CRUD universal yang terlalu generik.
- Plugin marketplace dan package distribution publik.
- Multi-tenancy, microservices, dan deployment multi-region.
- Penggantian fitur default starter kit.

## Kill Criteria

Hentikan perluasan framework jika generator belum dapat menghasilkan satu module
contoh lengkap yang bisa boot, diuji, dan dihapus/diulang secara aman.
