## Technical Baseline

| Area | Standard |
|---|---|
| Runtime | PHP 8.4+, Laravel 13 |
| Frontend | React, TypeScript strict, Inertia.js, Vite |
| UI | Tailwind CSS, shadcn/ui, Lucide |
| Database | MySQL |
| Cache/Queue | Redis |
| Routes | Ziggy; no generated Wayfinder route layer |
| Authorization | Spatie Permission plus policy rules |
| Media | Spatie Media Library when a module requires media |
| Tests | Pest/PHPUnit, Vitest, Playwright, axe-core |

Laravel React starter kit menyediakan authentication, profile, notification, dan
settings dasar. Baseline tidak membangun ulang capability tersebut. Module
SystemSetting menyediakan global runtime configuration seperti rate limit,
idempotency, session timeout, branding, design token, dan operational recovery
target.

## Dependency Rules

Wayfinder dan Laravel Boost dilarang berada pada composer.json, package.json,
config, source code, generated output, atau dokumentasi. Route frontend memakai
Ziggy.

packages/StarterKit memakai Composer path repository pada development. Package
menyediakan generator, module registry, console, stub engine, contract, dan
kernel service; business module tetap berada pada app/Modules.

Cross-module dependency wajib memakai public contract, DTO, event, atau shared
value object yang telah disepakati. Direct concrete dependency dilarang dan
setiap module memiliki communication layer sendiri.

Pola eksekusi mengikuti `03.12-MODULE-COMMUNICATION-AND-EXECUTION.md`:
Application Action dan Query adalah baseline; Command Bus, Integration Event,
Queue/Job, Facade, dan Shared Kernel hanya ditambahkan jika ada consumer atau
kebutuhan nyata yang terdokumentasi.

## Module Implementation Contract

Module lokal berada di app/Modules/{Domain}/{SubModule}. Profile system
menghasilkan urutan baseline berikut:

1. AccessControl
2. UserManagement
3. AuditLog
4. SystemSetting

Setiap module wajib memiliki module.json, module.php, ServiceProvider.php,
permissions.php, README.md, layer DDD-lite, database boundary, frontend
ownership, dan test boundary. Permission identity berupa metadata lokal module;
AccessControl melakukan discovery dan sync.

Module invalid hanya dinonaktifkan. Module valid lain tetap bootstrap dan
diagnostic wajib tersedia melalui registry/console.

## Identifier and Data Rules

- Semua primary key, foreign key, route identifier, DTO identifier, event
  identifier, fixture, dan API resource identifier menggunakan ULID.
- Migration memakai $table->ulid('id')->primary() dan
  $table->foreignUlid('...') sesuai database design.
- Soft delete tidak menghapus audit record; FK actor menggunakan SET NULL bila
  actor dihapus.
- Secret, token, password, credential, dan sensitive payload tidak boleh masuk
  ke log, audit metadata, API response, atau plain SystemSetting.

## API and Runtime Contract

Internal API menggunakan REST /api/v1, response envelope standar, validation
error 422, authentication/authorization 401/403, dan resource absence 404.
Pagination default serta batas per_page mengikuti 02.01-API-SPEC.md.

- Rate limit tetap per actor dan dikonfigurasi melalui SystemSetting.
- Mutating request sensitif menggunakan Idempotency-Key.
- Idempotency disimpan 24 jam dengan payload hash dan response tersimpan.
- Perubahan SystemSetting langsung aktif setelah validation dan selalu diaudit.
- Correlation ID dan job ID menggunakan ULID serta diteruskan ke integration
  event atau queue workflow yang memang menggunakannya.

## Frontend Implementation Contract

```text
resources/js/
|-- components/       # shared UI only
|-- layouts/
|-- pages/System/
|   |-- AccessControl/
|   |-- UserManagement/
|   |-- AuditLog/
|   `-- SystemSetting/
|-- hooks/
|-- lib/
|-- types/
`-- routes/
```

Komponen khusus module berada di dalam folder module. Shared component berada
di components/ui atau components/shared. Form memakai schema validation,
keyboard navigation, focus management, dan pola WCAG 2.2 AA.

## Configuration Contract

Environment menyimpan deployment secret dan infrastructure connection. Runtime
setting yang aman untuk diubah saat aplikasi berjalan disimpan melalui
SystemSetting. Hanya SuperSystem yang boleh mengubah SystemSetting; perubahan
memerlukan reason, audit actor, before/after value, correlation ID, dan hasil
validation.

Baseline default:

| Setting | Default |
|---|---|
| Idle session timeout | 30 menit |
| Absolute session lifetime | 12 jam |
| Idempotency retention | 24 jam |
| Audit retention | Minimum 1 tahun |
| RTO | Maksimum 4 jam, melalui `operations.rto_hours` |
| RPO | Maksimum 24 jam, melalui `operations.rpo_hours` |

MFA memakai capability starter kit dan bersifat opsional untuk SuperSystem.
Target impersonation SuperSystem selalu ditolak dan reason impersonation wajib
sebelum session dimulai.

## Quality and Verification Contract

Local quality gate:

```bash
vendor/bin/pint --test
vendor/bin/phpstan analyse
php artisan test
npm run lint
npm run typecheck
npm run test
npm run build
```

CI wajib menjalankan quality gate, dependency audit, CodeQL, migration/schema
verification, generator tests, module discovery tests, dan critical browser
flows. Threshold coverage mengikuti 03.01-CODING-STANDARD.md.

Acceptance minimum sebelum module ready:

- manifest dan permission schema valid;
- migration ULID lulus;
- contract/policy/audit test lulus;
- frontend critical flow lulus;
- output generator reproducible dan cleanup aman;
- tidak ada Wayfinder, Laravel Boost, secret, atau dependency boundary violation.

## Operational Contract

Application memakai structured logging, correlation ID, health/diagnostic
command, queue failure handling, Redis monitoring, database backup, dan audit
retention policy. Deployment harus dapat menjalankan migration secara aman,
melakukan rollback sesuai release plan, dan memverifikasi module registry
sebelum traffic dibuka.
