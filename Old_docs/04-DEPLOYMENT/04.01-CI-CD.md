## Objectives

CI/CD harus memberikan evidence otomatis bahwa setiap perubahan:

- mengikuti coding standard dan module boundary;
- lulus test, static analysis, build, accessibility, dan security gate;
- tidak mengandung Wayfinder atau Laravel Boost;
- aman untuk dipromosikan ke environment berikutnya;
- dapat diulang dan didiagnosis tanpa instruksi lisan.

CI tidak menggantikan verification lokal pada Laragon. Local dan CI harus memakai
versi runtime yang dikunci melalui composer.lock, package-lock.json, dan workflow
matrix yang terdokumentasi.

Runtime CI saat ini memakai PHP 8.4 dan Node.js `24.12.0` dari `.node-version`.
Dependency dipasang melalui `composer install` dan `npm ci` dari lockfile.

## Branch and Pull Request Policy

- main adalah protected branch dan branch release baseline.
- feature/<type>/<scope>/<description> untuk feature/fix/refactor/docs/test/chore.
- hotfix/<scope>/<description> hanya untuk production correction.
- release/<version> hanya untuk persiapan release.
- Semua perubahan masuk melalui pull request.
- Direct push, force push, dan merge tanpa required checks dilarang.
- Squash merge wajib untuk PR biasa; merge commit hanya untuk release procedure.
- Minimal satu reviewer dan CODEOWNERS approval untuk perubahan security,
  database, deployment, kernel, atau module contract.

## Pipeline Triggers

| Trigger | Pipeline |
|---|---|
| Pull request | Quality, test, security, build, artifact |
| Push main | Full verification dan deploy ke staging bila disetujui |
| Release tag | Full verification, artifact final, deployment approval |
| Schedule | Dependency/security scan dan maintenance check |
| Manual dispatch | Re-run atau environment deployment dengan approval |

## Pull Request Pipeline

Urutan job:

1. Checkout repository.
2. Setup PHP 8.4, Composer, Node.js, dan npm.
3. Install Composer dependencies dengan lock file.
4. Install npm dependencies dengan lock file.
5. Validate dependency tree dan forbidden package/reference.
6. Run Pint check.
7. Run PHPStan/Larastan.
8. Run ESLint dan TypeScript check.
9. Run unit, feature, integration, contract, and generator tests.
10. Verify coverage thresholds.
11. Run frontend tests and production build.
12. Run migration fresh-install and schema verification.
13. Run Playwright critical flows and axe-core.
14. Run CodeQL and OWASP Dependency-Check.
15. Publish test, coverage, security, and build artifacts.

Jobs yang tidak bergantung satu sama lain dapat berjalan paralel setelah
dependency installation selesai. Failure pada required job memblokir merge.

## GitHub Actions Requirements

Workflow wajib:

- menjalankan pada Ubuntu CI runner untuk parity deployment;
- menyediakan MySQL dan Redis service container;
- menggunakan cache Composer/npm tanpa melewati lock file;
- memakai least-privilege permissions;
- tidak mencetak secret ke log;
- mengunggah artifact dengan retention policy;
- membatasi concurrency agar deployment lama dapat dibatalkan secara aman;
- menggunakan environment protection untuk staging/production;
- mem-pin action ke commit SHA immutable dan meninjau update dependency.

Workflow repository saat ini:

- `.github/workflows/tests.yml` dengan nama `quality`: static/frontend,
  backend coverage, MySQL fresh, dan MySQL upgrade legacy;
- `.github/workflows/security.yml`: dependency audit, CodeQL JavaScript dan
  TypeScript, serta OWASP Dependency-Check;
- `.github/workflows/browser.yml`: Playwright dan axe-core pada Chromium
  desktop/mobile;
- deploy-staging.yml: artifact promotion dan smoke test;
- deploy-production.yml: approval, migration, deploy, health check, rollback hook.

Workflow deployment belum dibuat karena target environment masih menjadi open
decision. Action pihak ketiga yang sudah dipakai dipin ke commit SHA immutable.

## Required Quality Gates

| Gate | Requirement |
|---|---|
| PHP formatting | Pint check lulus |
| PHP static analysis | PHPStan/Larastan lulus |
| Frontend lint/type | ESLint dan TypeScript lulus |
| Tests | Semua required test suite lulus |
| Coverage | Threshold dari 03.01-CODING-STANDARD.md |
| Build | Frontend production build lulus |
| Database | Fresh migration dan upgrade verification lulus |
| Browser | Critical Playwright dan axe-core flow lulus |
| Security | Tidak ada critical/high finding terbuka |
| Dependency policy | Wayfinder/Laravel Boost tidak ditemukan |
| Module | Discovery, manifest, permission, dan generator test lulus |

### Coverage Threshold

Backend memakai PCOV dan report Clover/JUnit. Threshold statement per layer:

| Layer | Minimum |
|---|---:|
| Domain | 90% |
| Application | 85% |
| Policy dan middleware security | 90% |
| Infrastructure | 75% |
| API dan critical use case | 80% |
| Generator framework | 85% |

Frontend memakai Vitest V8 dengan minimum 80% untuk statement, branch,
function, dan line pada file critical yang masuk allowlist coverage.

### Security Gate

- CodeQL hanya menganalisis JavaScript dan TypeScript karena CodeQL tidak
  menyediakan language support PHP.
- PHP diperiksa melalui PHPStan/Larastan, Pest coverage, authorization test,
  Composer audit, dan OWASP Dependency-Check.
- SARIF dengan `security-severity` minimal 7 atau level `error` memblokir job.
- OWASP Dependency-Check memakai batas CVSS 7 dan image yang dipin ke digest.
- Dependabot memeriksa Composer, npm, dan GitHub Actions setiap minggu dengan
  cooldown lima hari.

### Artifact dan Retention

- Evidence test, coverage, build, schema tanpa data, dan browser disimpan 14
  hari.
- Report CodeQL dan OWASP disimpan 30 hari.
- Artifact browser hanya mengizinkan report JSON dan screenshot kegagalan.
  Database, `.env`, session, cookie, token, trace, video, local storage, serta
  application log dilarang.
- Dump MySQL hanya berisi schema tanpa data dan tanpa komentar server.

## Environment Promotion

Flow standar:

Laragon local verification → Pull Request CI → main CI → staging → Approval →
production. Staging/production dapat menggunakan DigitalOcean Ubuntu via SSH
atau hosting cPanel sesuai project turunan.

Baseline pertama menetapkan Laragon sebagai local environment. DigitalOcean
Droplet Ubuntu LTS via SSH adalah deployment option utama, sedangkan cPanel
adalah option kompatibel untuk project turunan. Staging dan production wajib
menggunakan artifact dan release evidence yang sama, bukan build ulang manual.
Database migration dijalankan sebagai release step terkontrol dan harus memiliki
rollback/forward-fix procedure.

## Deployment Safety

Sebelum deployment:

- backup dan restore verification tersedia;
- migration compatibility telah diverifikasi;
- required environment variables tersedia;
- health check dan rollback command tersedia;
- audit/logging/monitoring aktif;
- deployment approval tercatat.

Setelah deployment:

- jalankan health check;
- jalankan module registry/discovery diagnostic;
- jalankan smoke test authentication starter kit dan baseline module;
- verifikasi queue, Redis, database, dan error rate;
- simpan deployment evidence dan release identifier.

Jika health check gagal, deployment dihentikan dan rollback atau forward-fix
dijalankan sesuai release runbook. Migration irreversible tidak boleh dijalankan
tanpa explicit approval dan recovery plan.

## Secrets and Permissions

- Secret disimpan pada GitHub Actions Environment Secrets atau secret manager
  VPS, tidak pada repository.
- Separate credentials untuk CI, staging, dan production.
- SSH deployment memakai dedicated deploy user, SSH key khusus per environment,
  known_hosts verification, dan least privilege bila target mendukung SSH.
- cPanel deployment memakai account-scoped credential/API atau SSH bila tersedia;
  credential tidak boleh menggunakan root dan wajib disimpan sebagai secret.
- Token/key deployment memiliki scope minimum dan tidak memakai root login.
- Production approval tidak boleh hanya bergantung pada branch name.
- Log dan artifact wajib melalui redaction review.

## Local-to-CI Verification

Developer sebelum membuka PR menjalankan pada Laragon:

- php artisan about;
- php artisan migrate:fresh;
- composer validate;
- vendor/bin/pint --test;
- vendor/bin/phpstan analyse;
- php artisan test;
- npm run lint:check;
- npm run types:check;
- npm run test:coverage;
- npm run test:e2e pada runtime browser disposable;
- npm run build.

Perbedaan versi lokal dan CI dicatat sebagai failure yang harus diperbaiki,
bukan diabaikan.

## Open Decisions

- **OD-CICD-001:** Topology staging/production dan pilihan target per project
  belum ditetapkan; DigitalOcean Ubuntu dan cPanel tetap supported options.
- **OD-CICD-002:** Deployment strategy pada VPS belum ditetapkan: release
  directory plus symlink, atomic archive, atau blue/green.
- **OD-CICD-004:** SSH hardening, cPanel capability, firewall, backup
  destination, dan monitoring provider belum ditetapkan per target.
- **OD-CICD-005:** Target smoke test URL/environment variable belum ditetapkan.

`OD-CICD-003` selesai pada 20 Agustus 2026. Retention evidence quality/browser
ditetapkan 14 hari dan report security 30 hari. Retention audit deployment final
akan mengikuti target deployment ketika `OD-CICD-001` diputuskan.

## Acceptance Criteria

- PR yang gagal pada required gate tidak dapat merge.
- Workflow menghasilkan artifact test, coverage, security, dan build.
- Push main dapat mempromosikan artifact ke staging setelah approval.
- Deployment production memerlukan protected environment approval.
- Failed health check menghentikan rollout dan memicu rollback/forward-fix path.
- Laragon quickstart dan local quality commands terdokumentasi serta berhasil.
