# Purpose

Dokumen ini menjelaskan kebutuhan bisnis tanpa membahas implementasi teknis.

---

# Business Background

Setiap project baru membutuhkan fondasi Laravel yang sama: struktur module,
konvensi, konfigurasi, dependency policy, testing, dan deployment. Saat ini
keputusan tersebut mudah berulang, tersebar, dan bergantung pada pengetahuan
pembuat project.

Starter kit ini diperlakukan sebagai produk internal reusable yang membantu
membuat project Laravel baru secara konsisten dan dapat dipelihara lintas
project.

---

# Business Problems

| ID | Problem |
|----|----------|
| BR-001 | Setup project baru memerlukan keputusan dan pekerjaan berulang. |
| BR-002 | Struktur module dan konvensi berbeda antar project jika dibuat manual. |
| BR-003 | AI dan developer baru tidak memiliki sumber acuan yang executable. |
| BR-004 | Perubahan dependency dan arsitektur sulit diverifikasi secara konsisten. |
| BR-005 | Pembuatan module, test, dan dokumentasi dasar memakan waktu manual. |

---

# Business Objectives

| ID | Objective |
|----|-----------|
| BO-001 | Mempercepat bootstrap project Laravel baru melalui baseline reusable. |
| BO-002 | Menjamin setiap module mengikuti DDD-lite modular monolith. |
| BO-003 | Menjadikan dokumentasi acuan yang dapat dijalankan developer dan AI. |
| BO-004 | Mengurangi drift dependency melalui policy dan verification. |
| BO-005 | Menyediakan jalur standar untuk generator module dan module console. |

---

# Expected Benefits

- Waktu bootstrap project dan module lebih singkat.
- Struktur dan naming lebih konsisten.
- Onboarding developer dan AI lebih cepat.
- Review arsitektur, security, test, dan deployment lebih mudah.
- Perubahan baseline dapat dilacak melalui ADR dan changelog.

---

# Business Processes

1. Owner memilih atau membuat project dari starter kit.
2. Developer memverifikasi stack dan dependency policy.
3. Developer membuat module melalui generator dan module console.
4. Generator menghasilkan struktur, contract, event, test, dan dokumentasi dasar.
5. QA memverifikasi acceptance criteria dan output generator.
6. DevOps menjalankan setup, CI/CD, release, rollback, dan operasi berdasarkan
   dokumentasi.
7. Perubahan lintas project dikembalikan ke baseline melalui review dan ADR.

---

# Business Constraints

- Baseline pertama harus dapat diverifikasi end-to-end sebelum diperluas.
- Starter kit menggunakan Laravel React starter kit bawaan Laravel 13.
- Auth, notification, profile, dan settings bawaan tidak dibangun ulang.
- Wayfinder dan Laravel Boost tidak boleh digunakan.
- Fitur yang belum diputuskan ditandai sebagai `Open Decision`.

---

# Assumptions

- Pengguna utama adalah owner/architect dan AI coding assistant.
- Tim developer menjadi pengguna berikutnya.
- Project memakai PHP 8.4+, Laravel 13, React, Inertia, TypeScript, Vite,
  shadcn/ui, PostgreSQL, Redis, Ziggy, dan package Spatie yang disetujui.
- Arsitektur target adalah DDD-lite Modular Monolith, domain-driven,
  contract-based, dan event-driven.

---

# Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Generator terlalu luas sebelum vertical slice tervalidasi. | High | Batasi baseline pada module generator, console, AccessControl, user management, dan audit log. |
| Konvensi berubah antar project. | High | Kunci manifest, ADR, contract, dan verification matrix. |
| Audit log menyimpan data sensitif. | High | Terapkan allowlist metadata, redaction, access control, dan retention policy. |
| Starter kit Laravel berubah pada release berikutnya. | Medium | Tetapkan compatibility matrix dan upgrade procedure. |
| Dokumentasi tertinggal dari implementasi. | Medium | Jadikan acceptance criteria dan review documentation sebagai release gate. |
