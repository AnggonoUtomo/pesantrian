# Business Terms

| Term | Description |
|------|-------------|
| User | Identitas yang dapat melakukan aktivitas pada aplikasi. |
| Administrator | Actor yang memiliki tanggung jawab pengelolaan sistem; bukan otomatis berarti semua permission. |
| Super System | Privileged baseline role dengan full access melalui policy/guard khusus; hanya terlihat oleh pemegang role tersebut. |
| Impersonation | Session sementara ketika actor berwenang bertindak sebagai user target dengan actor asli tetap dapat ditelusuri. |
| Actor | User, system, atau integration yang menjalankan sebuah action. |
| Role | Kumpulan permission yang diberikan kepada user atau subject. |
| Permission | Hak spesifik untuk melakukan action terhadap resource atau capability. |
| Subject | Entitas yang menjadi target authorization, biasanya user atau team. |
| Audit Log | Catatan immutable atau append-only mengenai aktivitas penting dan actor-nya. |

# Technical Terms

| Term | Description |
|------|-------------|
| API | Application Programming Interface; kontrak komunikasi yang dapat dipanggil client. |
| DTO | Data Transfer Object; object untuk membawa data antar boundary. |
| Entity | Object domain yang memiliki identity dan lifecycle. |
| Value Object | Object domain yang ditentukan oleh value, bukan identity. |
| Repository | Abstraksi persistence untuk aggregate atau entity; bukan business rule. |
| Application Service | Orchestrator use case; tidak menjadi tempat seluruh business logic. |
| Domain Service | Logic domain yang tidak cocok ditempatkan pada satu entity atau value object. |
| Infrastructure Adapter | Implementasi detail external system, database, filesystem, queue, atau framework. |
| Event | Notifikasi bahwa sesuatu telah terjadi; dapat berupa domain event atau integration event. |
| Command | Permintaan untuk melakukan perubahan atau action. |
| Contract | Boundary/interface yang mendefinisikan perilaku tanpa mengikat implementasi. |
| Port | Contract yang digunakan domain/application untuk berkomunikasi keluar. |
| Adapter | Implementasi port untuk teknologi atau external system tertentu. |
| Manifest | Metadata module yang mendefinisikan identity, version, dependency, status, path, dan provider. |
| Bootstrap | Proses menyiapkan application dan service sebelum menerima request atau command. |
| Idempotent | Operasi yang dapat dijalankan ulang dengan hasil akhir yang sama. |
| ULID | Universally Unique Lexicographically Sortable Identifier; identifier yang digunakan sebagai primary key dan foreign key baseline. |

# Naming Convention

Gunakan istilah canonical pada tabel di atas di seluruh dokumentasi, source
code, command, test, dan output generator.

- Gunakan `module`, bukan bergantian dengan `package`, `component`, atau `feature`
  jika yang dimaksud adalah boundary dengan manifest dan lifecycle.
- Gunakan `permission` untuk hak spesifik dan `role` untuk kumpulan permission.
- Gunakan `application service` untuk orkestrasi use case; jangan menyebut semua
  class business sebagai `service`.
- Gunakan `domain event` untuk event internal domain dan `integration event`
  untuk event lintas boundary atau external integration.
- Gunakan `module console` untuk CLI pengelolaan module; gunakan `Artisan`
  hanya ketika merujuk pada CLI Laravel secara umum.
- `Wayfinder` dan `Laravel Boost` adalah forbidden dependency, bukan alternatif
  untuk Ziggy.

## Naming Rules

- Class dan interface menggunakan PascalCase.
- Method, variable, dan config key menggunakan camelCase atau konvensi Laravel
  yang berlaku pada konteksnya.
- Module dan submodule menggunakan PascalCase pada namespace dan kebab-case
  hanya jika digunakan sebagai slug atau command argument.
- Requirement memakai prefix `BR`, `BO`, `FR`, `NFR`, `BL`, atau `US`.
- Decision memakai prefix `OD` untuk open decision dan `ADR` untuk decision
  yang telah disetujui.
