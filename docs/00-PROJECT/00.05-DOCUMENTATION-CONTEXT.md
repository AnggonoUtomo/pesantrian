## Mission

Membangun reusable Laravel Engineering Starter Kit yang memungkinkan project
baru, module, test, dan deployment dibuat dengan pola yang konsisten serta dapat
diikuti tanpa instruksi lisan tambahan.

## Product Context

Ini adalah engineering platform internal, bukan aplikasi bisnis tertentu dan
bukan pengganti Laravel. Baseline pertama berfokus pada vertical slice yang
dapat diverifikasi end-to-end: starter verification, module contract, generator,
module console, `AccessControl`, `UserManagement`, `AuditLog`, dan `SystemSetting`.

## Fixed Technical Decisions

- PHP 8.4+
- Laravel 13 React starter kit bawaan
- Inertia.js, React, TypeScript, Vite
- Tailwind CSS dan shadcn/ui
- PostgreSQL sebagai database utama
- Redis untuk cache dan queue
- Ziggy untuk route integration frontend
- Package Spatie yang disetujui, termasuk Media Library bila diperlukan
- DDD-lite Modular Monolith
- Domain-driven boundaries
- Contract/port-based dependencies
- Event-driven communication ketika sesuai
- Cross-module communication wajib melalui contract atau public event layer.
- Correlation ID, job ID, dan actor ID menggunakan ULID.

## Forbidden Dependencies

- Wayfinder tidak boleh ada pada composer dependency, source, configuration,
  generated output, atau dokumentasi implementasi.
- Laravel Boost tidak boleh ada pada composer dependency, source, configuration,
  generated output, atau dokumentasi implementasi.
- Penggantian dependency forbidden harus menggunakan Ziggy atau pattern resmi
  yang disetujui melalui ADR.

## Documentation Authority

Urutan authority dari konteks menuju delivery:

1. `00-PROJECT`: visi, business need, scope, glossary, dan baseline direction.
2. `01-REQUIREMENTS`: capability, quality target, user story, dan acceptance.
3. `02-DESIGN`: boundary, data, API, security, dan UI/UX solution.
4. `03-IMPLEMENTATION`: coding, folder, generator, module, test, dan workflow.
5. `04-DEPLOYMENT`: environment, CI/CD, release, rollback, dan operations.
6. `05-DECISIONS`: ADR, changelog, known issues, dan exception register.
7. `06-FRAMEWORK`: spesifikasi framework setelah baseline `00–05` stabil.
8. `07-KERNEL`: detail runtime kernel yang harus mengikuti contract `00–06`.

Jika dua dokumen konflik, jangan memilih diam-diam. Catat conflict, ikuti
dokumen dengan authority lebih tinggi, dan buat atau perbarui ADR.

## Context Loading Order

### Untuk Task Baru

1. Baca file ini dan `AGENTS.md`.
2. Baca scope serta glossary yang relevan.
3. Baca requirement dan acceptance criteria.
4. Baca design contract terkait.
5. Baca implementation pattern dan test plan.
6. Baca deployment impact sebelum mengubah config, migration, queue, atau secret.
7. Gunakan error output dan test result sebagai context iterasi berikutnya.

### Untuk AI Coding Assistant

- Jangan mengarang requirement yang belum ada.
- Cari pattern yang sudah digunakan sebelum membuat pattern baru.
- Perlakukan `Open Decision` sebagai unresolved.
- Jangan mengubah fixed decision tanpa persetujuan dan ADR.
- Sebelum coding, sebutkan file yang relevan dan acceptance criteria.
- Setelah coding, laporkan test, risiko, dan dokumentasi yang terdampak.

## Baseline Completion

Baseline dianggap siap apabila:

- project baru dapat boot dari quickstart pada mesin bersih;
- dependency policy dapat diverifikasi otomatis;
- generator menghasilkan module deterministic dan conflict-safe;
- module console dapat inspect dan validate module;
- initial modules memiliki contract, event, test, dan dokumentasi;
- CI, deployment staging, rollback, dan restore drill terdokumentasi;
- tidak ada keputusan kritis yang hanya berada di percakapan.

## Project Intake Context

Context global ini mendukung tiga mode penggunaan: greenfield, existing starter
kit, dan module extension. Sebelum membuat dokumentasi project turunan, AI wajib
menginventaris source code, starter kit, package, module, migration, route,
permission, event, dan capability yang sudah ada. Dokumentasi spesifik project
dibuat pada `Projects/{project-slug}` menggunakan `Projects/_TEMPLATE`.

Pekerjaan project turunan wajib dipecah menjadi increment kecil menggunakan
incremental-implementation. Setiap increment memiliki acceptance criteria,
focused test, verification evidence, execution log, dan documentation update.

## Acceptance Criteria

- Pembaca dapat menentukan dokumen berikutnya dari authority map.
- AI dapat membedakan fixed decision, requirement, design, task, dan open decision.
- Semua istilah penting mengacu ke `00.02-GLOSSARY.md`.
- Tidak ada instruksi yang bertentangan dengan `00.03-PROJECT-SCOPE.md`.
- Context pack dapat digunakan tanpa membaca seluruh repository sekaligus.
