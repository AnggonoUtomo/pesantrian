## Requirement Format

Setiap requirement memiliki ID, actor, priority, status, precondition, main
flow, exception flow, dan acceptance criteria. Requirement menjelaskan behavior;
detail class, folder, dan teknologi berada pada dokumen design/implementation.

## Authentication Boundary

Login, logout, password reset, dan authentication flow bukan feature yang
dibangun ulang oleh baseline. Baseline hanya menyediakan integration contract
terhadap auth starter kit dan menghasilkan audit event bila action tersebut
memenuhi policy audit aplikasi.

## Command Contract

Command utama menggunakan pola colon Laravel Artisan:

```text
php artisan module:make AccessControl --domain=System --force --yes --json
php artisan module:list
php artisan module:validate --json
php artisan module:discover
php artisan module:validate
```

Format subcommand `module make` dapat dipertimbangkan kemudian, tetapi bukan
contract baseline pertama.

## Common Acceptance Rules

- Setiap requirement `Must` memiliki automated test atau verification procedure.
- Error command memiliki exit code non-zero dan message yang actionable.
- Command tidak menimpa source code tanpa `--force`.
- Behavior yang mengubah authorization atau audit memiliki security test.
- Requirement yang berubah memperbarui traceability matrix dan revision history.
