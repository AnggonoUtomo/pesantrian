## Purpose

Mendefinisikan produk, pengguna, capability, prioritas, dan success metrics
untuk starter kit sebelum diterjemahkan menjadi design dan implementation task.

## Product Overview

### Product Name

Laravel Engineering Starter Kit

### Product Type

Reusable internal engineering platform dan baseline project generator.

### Product Description

Starter kit menyediakan fondasi Laravel 13 yang konsisten untuk project baru,
termasuk stack verification, architecture convention, module contract, generator,
module console, testing, documentation, dan delivery guidance. Produk ini
menghasilkan baseline project; bukan aplikasi bisnis end-user.

## Product Problem

Project Laravel baru sering mengulang keputusan dependency, struktur module,
authorization, audit, testing, dan deployment. Tanpa source of truth yang
executable, developer dan AI menghasilkan implementasi yang berbeda antar project.

## Product Goals

- Membuat project Laravel baru dari baseline yang repeatable.
- Menghasilkan module lengkap melalui command yang aman dan deterministic.
- Memberikan context yang dapat dipakai AI tanpa knowledge lisan.
- Menyediakan System module dengan `AccessControl`, `UserManagement`, dan
  `AuditLog` sebagai vertical slice pertama.
- Menjaga starter kit dapat di-upgrade lintas project melalui internal package
  dan dokumentasi versioned.

## Non-Goals

- Menjadi aplikasi bisnis atau SaaS.
- Menggantikan Laravel React starter kit.
- Membangun ulang authentication, notification, profile, atau settings bawaan.
- Menyediakan CRUD/API generator universal pada baseline pertama.
- Menjadi public package atau marketplace pada milestone awal.
- Menambahkan multi-tenancy, microservices, atau multi-region deployment.

## Initial Module Product Contract

### System

Module induk untuk capability infrastructure dan cross-cutting yang dipakai
project. Struktur awal: `app/Modules/System/{Submodule}`.

### AccessControl

Mengelola role, permission, assignment role/user, optional direct permission,
policy, guard, effective allow, dan audit event. Tidak memiliki explicit deny
model pada baseline.

Role baseline bernama `Super System`. Role ini dibuat melalui initialization
atau seeder AccessControl, bukan di-hardcode sebagai bypass tersebar di
framework. `Super System` memiliki full access melalui policy/guard khusus,
termasuk mengelola role, permission, dan audit log. Role serta permission
privileged tersebut hanya terlihat oleh user yang memiliki `Super System`.

Project turunan dapat membuat role `Super Admin` atau role lain melalui
AccessControl tanpa menjadikannya bagian dari framework baseline.

### UserManagement

Mengelola create, read, update, active/inactive, soft delete, dan assignment
role. Menyediakan impersonation user melalui permission khusus
`user.impersonate`. Authentication, password, dan profile tetap terintegrasi
dengan starter kit.

Impersonation wajib meminta reason sebelum session dimulai dan mencatat actor
asli, target user, start time, end/exit, reason, correlation ID, dan audit event.
Identitas actor asli tidak boleh hilang
dari audit trail. User dengan role `Super System` selalu menjadi target yang
tidak eligible untuk impersonation, termasuk oleh actor non-`Super System`.

### AuditLog

Menyimpan audit record append-only dengan actor, action, subject, timestamp,
correlation ID, filtered metadata, dan retention minimal satu tahun. Auditor
non-`Super System` hanya dapat membaca record sesuai scope, sedangkan
`Super System` dapat membaca seluruh record.

### SystemSetting

Mengelola setting runtime global tervalidasi untuk rate limit, idempotency
key/response retention selama 24 jam dengan payload hash, serta idle session
timeout dan absolute session lifetime. Hanya `Super System`
yang dapat mengubah setting. Perubahan langsung aktif setelah validation
berhasil dan wajib mencatat actor, key, nilai sebelum/sesudah, reason, timestamp,
correlation ID, dan audit event. Secret tidak boleh disimpan sebagai plain setting.

## Primary User Flows

1. Owner membuat project dari internal starter kit.
2. Developer memverifikasi environment dan forbidden dependency.
3. Developer menjalankan `php artisan module:make System AccessControl`.
4. Generator memvalidasi naming, conflict, dan menghasilkan struktur module.
5. Developer menjalankan module discovery dan validation.
6. Developer mengimplementasikan role/permission/policy dan test.
7. QA menjalankan acceptance test dan NFR verification.
8. DevOps menjalankan CI, staging deployment, release, dan rollback drill.

## Product Constraints

- Laravel 13 dan PHP 8.4+.
- React starter kit bawaan Laravel 13 dengan Inertia, TypeScript, Vite,
  Tailwind, dan shadcn/ui.
- PostgreSQL, Redis, Ziggy, dan package Spatie yang disetujui.
- Semua identifier tabel menggunakan ULID.
- Wayfinder dan Laravel Boost forbidden.
- Generator fail-safe; overwrite hanya dengan `--force`.
- Invalid module menggunakan isolated block.

## Success Metrics

| Metric | Baseline Target |
|---|---|
| Clean setup success | Project dapat boot dari quickstart pada mesin bersih |
| Time to first module | Developer dapat membuat module pertama dari dokumentasi |
| Generator safety | Tidak ada overwrite tanpa `--force` |
| Generator repeatability | Re-run tidak menghasilkan duplicate structure |
| Documentation usability | AI/developer menyelesaikan task tanpa instruksi lisan |
| Quality gate | Semua `Must` requirement dan critical test lulus |
| Runtime baseline | Availability 99.5%, P95 endpoint biasa ≤ 500 ms |
| Security baseline | Tidak ada forbidden dependency dan audit redaction lulus |

## Release Acceptance

Produk baseline dapat dirilis jika:

- PRD feature `Must` memiliki functional requirement dan acceptance test.
- Generator menghasilkan module lengkap dengan manifest, provider, test, dan README.
- AccessControl, UserManagement, dan AuditLog memiliki integration verification.
- Quickstart dapat dijalankan oleh developer baru dan AI coding assistant.
- CI, staging deployment, rollback, dan restore procedure lulus.
- Known issue serta open decision dicatat.
