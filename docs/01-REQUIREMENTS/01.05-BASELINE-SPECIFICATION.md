## Purpose

Mendefinisikan kontrak minimum yang harus dipenuhi sebelum baseline dianggap
usable dan boleh menjadi fondasi project turunan.

## Fixed Baseline Decisions

- Framework distribution awal: satu package `packages/StarterKit`.
- Application module path: `app/Modules/System/{Submodule}`.
- Module metadata: `module.json`; runtime config hanya melalui `module.php`.
- Permission identity module: `permissions.php` pada setiap module.
- Command utama memakai colon syntax Laravel Artisan.
- Generator fail-safe; overwrite membutuhkan `--force` eksplisit.
- Invalid module diisolasi dan tidak memblokir module valid lainnya.
- Permission baseline hanya allow permission dan policy rule.
- Role privileged baseline bernama `SuperSystem`.
- User target `SuperSystem` selalu dilarang untuk impersonation.
- Impersonation memakai permission `user.impersonate` dan reason wajib.
- Auditor non-`SuperSystem` hanya melihat audit log sesuai scope.
- Audit log disimpan minimal satu tahun.
- Semua primary key dan foreign key menggunakan ULID.
- Rate limit tetap aktif per actor dan dikonfigurasi melalui module `SystemSetting`.
- Idempotency key dan response disimpan 24 jam dengan payload hash.
- Development memakai Composer path repository untuk `packages/StarterKit`.
- Runtime lokal terakhir terverifikasi pada PHP 8.4.16. Constraint PHP di
  `composer.json` masih `^8.3`, sehingga dukungan minimum konfigurasi Composer
  belum sama dengan policy runtime PHP 8.4+.
- Dependency lintas module wajib melalui contract/communication layer; direct
  dependency hanya untuk public event atau shared value object yang disepakati.
- Correlation ID, job ID, dan actor ID menggunakan ULID.

## Functional Contract

| BL-003 | Route integration | Route frontend memakai Ziggy dan tidak mengandalkan Wayfinder. |

| BL-006 | Module console | Console menyediakan make, list, discover, dan validate. |
| BL-007 | Discovery | Discovery berjalan saat bootstrap/cache build; module invalid diisolasi dengan diagnostic. |
| BL-008 | Repeatability | `--dry-run`, naming validation, conflict detection, summary, dan `--force` tersedia. |
| BL-009 | Initial modules | AccessControl, UserManagement, AuditLog, dan SystemSetting memiliki boundary serta contract terdokumentasi. |
| BL-010 | SuperSystem | Role dibuat melalui AccessControl initialization/seeder dan dilindungi policy/guard khusus. |
| BL-011 | User impersonation | Permission `user.impersonate`, reason wajib, explicit exit, actor traceability, dan target SuperSystem denial tersedia. |
| BL-012 | Scoped audit | Audit append-only dengan filtered metadata, retention minimal satu tahun, dan scoped visibility tersedia. |
| BL-014 | Session security | Idle timeout default 30 menit dan absolute lifetime default 12 jam dapat dikonfigurasi melalui SystemSetting. |
| BL-015 | Branding | Nama aplikasi, logo, favicon, theme, typography, light/dark preference, dan design token dapat dikonfigurasi melalui SystemSetting. |
| BL-013 | Verification | Baseline memiliki unit, feature, integration, smoke, security, dan schema verification minimum. |

## Command Contract

```bash
php artisan module:make AccessControl --domain=System --force --yes --json
php artisan module:list
php artisan module:validate --json
php artisan module:discover
php artisan module:validate
```

Command wajib mengembalikan exit code yang benar, diagnostic actionable, dan
tidak menimpa file tanpa `--force`.

## Module Boundaries

### AccessControl

Role, permission, role/user assignment, optional direct permission assignment,
policy, guard, `SuperSystem`, effective allow, dan security audit event. Tidak
ada explicit deny model pada baseline.

### UserManagement

Create, read, update, active/inactive, soft delete, role assignment integration,
dan impersonation dengan permission `user.impersonate`. Auth, password, dan
profile tetap menggunakan starter kit.

### AuditLog

Append-only actor/action/subject record dengan timestamp, correlation ID,
filtered metadata, reason impersonation, scoped visibility, dan retention
minimal satu tahun. Secret, token, credential, dan payload sensitif dilarang.

### SystemSetting

Mengelola setting runtime global tervalidasi untuk rate limit, idempotency,
session timeout, dan target recovery operations (`operations.rto_hours` serta
`operations.rpo_hours`)
retention/payload hash selama 24 jam, serta session timeout. Hanya `SuperSystem` yang dapat mengubah
setting; perubahan langsung aktif setelah validation dan mencatat actor, key,
nilai sebelum/sesudah, reason, timestamp, correlation ID, serta audit event.
Setting tidak menyimpan secret plain text.

## Non-Functional Contract

- Generator output deterministic dan idempotent.
- Error command actionable dan dapat diproses CI.
- Module tidak menyembunyikan dependency runtime.
- Semua table identifier memakai ULID.
- Setup baru dapat diverifikasi dari quickstart pada mesin bersih.
- Endpoint biasa memenuhi P95 ≤ 500 ms pada baseline workload.
- Availability target baseline production adalah 99.5% per bulan.
- UI baseline memenuhi WCAG 2.2 Level AA.

| Delivery | CI, staging deployment, rollback, restore drill |

## Open Decisions

- **OD-BL-005:** Nama resmi internal repository/package `StarterKit`.
- **OD-BL-006:** Hardware/environment detail untuk benchmark 100 concurrent users.
- **OD-BL-007:** Tool resmi untuk performance dan accessibility scan.
- **OD-BL-008:** Detail purge/archive mechanism setelah retention satu tahun.

## Definition of Done

Baseline diterima jika BL-001 sampai BL-013 memiliki automated verification
atau evidence procedure, quickstart dapat diikuti pada mesin bersih, dan tidak
ada Open Decision yang menghalangi implementasi vertical slice.
