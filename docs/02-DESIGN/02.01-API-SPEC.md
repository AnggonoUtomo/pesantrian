## API Boundary

Baseline menyediakan **internal application API**, bukan public API eksternal.
API dipakai oleh frontend Inertia/React, module internal, dan integration yang
disetujui. Public API memerlukan versioning, authentication, rate limit, dan ADR
terpisah sebelum dirilis.

## API Standard

- REST API dengan resource noun dan HTTP semantics standar.
- Base path: `/api/v1`.
- Request divalidasi sebelum application service dipanggil.
- Authorization diperiksa pada endpoint dan use case boundary.
- Identifier resource menggunakan ULID.
- Semua endpoint mendokumentasikan method, path, actor, authorization, request,
  response, error code, idempotency, dan acceptance tests.

## Response Envelope

### Success

```json
{
  "success": true,
  "message": "Users retrieved successfully.",
  "data": {},
  "meta": {}
}
```

### Error

```json
{
  "success": false,
  "message": "Validation failed.",
  "errors": {},
  "code": "VALIDATION_ERROR",
  "meta": {}
}
```

`data` berisi resource atau collection. `meta` berisi pagination, correlation
ID, dan metadata non-sensitive. `errors` tidak boleh mengembalikan secret,
stack trace, atau detail internal.

## HTTP Status

| Status | Usage |
|---|---|
| 200 | Successful read, update, action, atau delete response |
| 201 | Resource berhasil dibuat |
| 204 | Success tanpa response body bila memang diperlukan |
| 400 | Request malformed atau action tidak valid |
| 401 | Authentication tidak tersedia/valid |
| 403 | Authentication ada tetapi authorization ditolak |
| 404 | Resource tidak ditemukan atau tidak terlihat dalam scope |
| 409 | Conflict atau idempotency mismatch |
| 422 | Validation error |
| 429 | Rate/attempt limit terlampaui |
| 500 | Unexpected server error tanpa detail internal |

## Query Contract

Collection endpoint mendukung:

```text
?page=1
&per_page=25
&search=keyword
&sort=-created_at,name
&filter[status]=active
```

- Default `per_page` ditetapkan endpoint.
- Maximum `per_page` adalah 100.
- Field yang dapat dicari, di-filter, atau di-sort harus berupa allowlist.
- Sort prefix `-` berarti descending.
- Filter tidak boleh melewati authorization scope.

### Pagination Response

```json
{
  "success": true,
  "message": "Users retrieved successfully.",
  "data": [],
  "meta": {
    "current_page": 1,
    "per_page": 25,
    "total": 100,
    "last_page": 4
  }
}
```

Baseline menggunakan page pagination. Cursor pagination hanya boleh ditambahkan
untuk endpoint yang memiliki kebutuhan performance dan decision terdokumentasi.

## Idempotency

Endpoint create dan action sensitif wajib menerima `Idempotency-Key`, termasuk:

- create user, role, dan permission;
- role/direct permission assignment;
- start impersonation;
- action yang dapat menghasilkan audit event atau side effect berulang.

Server menyimpan hasil berdasarkan actor, endpoint, dan key sesuai retention
yang ditetapkan pada module `SystemSetting`. Baseline menyimpan key,
payload hash, dan response selama **24 jam**. Key yang sama dengan payload
berbeda menghasilkan `409 IDEMPOTENCY_CONFLICT`.

## Rate Limiting

Internal API tetap menggunakan rate limit per actor. Nilai limit tidak di-hardcode
di setiap endpoint; konfigurasi dikelola oleh module `SystemSetting`.

- Rate limit dapat dibedakan berdasarkan actor, capability, endpoint, atau
  kategori endpoint.
- Endpoint sensitif dan endpoint mahal wajib memiliki limit.
- Saat limit terlampaui, API mengembalikan `429` dengan retry metadata.
- Perubahan konfigurasi rate limit menghasilkan audit event.
- Default rate limit wajib terdokumentasi dan dapat diganti melalui policy
  `SystemSetting` atau environment/config resmi saat bootstrap.

## Baseline Endpoint Matrix

| Method | Endpoint | Capability | Authorization |
|---|---|---|---|
| GET | `/api/v1/users` | List user | User scope/read user |
| POST | `/api/v1/users` | Create user | User create |
| GET | `/api/v1/users/{user}` | Read user | User scope/read user |
| PATCH | `/api/v1/users/{user}` | Update/status user | User update |
| DELETE | `/api/v1/users/{user}` | Soft delete user | User delete |
| GET | `/api/v1/roles` | List role | Role read; privileged visibility protected |
| POST | `/api/v1/roles` | Create role | Role create |
| PATCH | `/api/v1/roles/{role}` | Update role | Role update |
| POST | `/api/v1/users/{user}/roles` | Assign role | Role assign |
| DELETE | `/api/v1/users/{user}/roles/{role}` | Revoke role | Role assign |
| POST | `/api/v1/users/{user}/permissions` | Direct permission assign | Permission assign |
| DELETE | `/api/v1/users/{user}/permissions/{permission}` | Revoke direct permission | Permission assign |
| GET | `/api/v1/permissions` | List permission | Permission read; privileged visibility protected |
| POST | `/api/v1/users/{user}/impersonation` | Start impersonation | `user.impersonate`; reason required; Super System target denied |
| DELETE | `/api/v1/impersonation` | End impersonation | Active actor session |
| GET | `/api/v1/audit-logs` | List audit log | Scope-based audit read; Super System all |
| GET | `/api/v1/audit-logs/{auditLog}` | Read audit record | Record scope authorization |

Endpoint matrix adalah baseline contract. Payload schema dan resource transformer
wajib ditulis pada implementation spec module sebelum endpoint dibuat. Detail
tersebut mencakup field wajib/optional, tipe ULID, validation, authorization,
idempotency, error response, dan acceptance test.

## Validation and Authorization

- Gunakan Form Request atau equivalent request contract.
- Policy/permission diperiksa server-side.
- Resource yang berada di luar scope dapat merespons `404` untuk mencegah
  information disclosure, sesuai security policy endpoint.
- `Super System` menggunakan policy/guard khusus dan tetap menghasilkan audit.
- Impersonation menampilkan actor asli serta target pada audit context.

## Error Codes

| Code | Meaning |
|---|---|
| `VALIDATION_ERROR` | Request tidak memenuhi schema |
| `UNAUTHENTICATED` | Session/authentication tidak valid |
| `FORBIDDEN` | Permission atau scope ditolak |
| `RESOURCE_NOT_FOUND` | Resource tidak ditemukan/terlihat |
| `CONFLICT` | State atau unique constraint conflict |
| `IDEMPOTENCY_CONFLICT` | Key dipakai untuk payload berbeda |
| `INVALID_MODULE` | Module metadata atau contract invalid |
| `IMPERSONATION_REASON_REQUIRED` | Reason impersonation kosong |
| `IMPERSONATION_TARGET_FORBIDDEN` | Target `Super System` tidak boleh di-impersonate |
| `INTERNAL_ERROR` | Unexpected error; detail internal disembunyikan |
