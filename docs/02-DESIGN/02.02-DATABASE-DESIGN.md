## Database Boundary

- PostgreSQL, satu database, satu schema `public`.
- Module memiliki ownership tabel dan migration boundary, bukan database terpisah.
- Table name menggunakan nama resource langsung tanpa prefix module.
- Persistence diakses melalui repository/application boundary.

## Identifier and Naming

- Semua primary key dan foreign key menggunakan ULID.
- Primary key bernama `id`; foreign key memakai `{entity}_id`.
- Integer auto-increment dan UUID tidak digunakan sebagai entity identifier.
- ULID diperlakukan sebagai opaque value dan konsisten pada model, API, event,
  DTO, factory, fixture, dan route binding.
- Table dan column menggunakan `snake_case`.
- Timestamp memakai `created_at` dan `updated_at`; soft delete memakai `deleted_at`.
- Foreign key dan field filter/search/sort wajib memiliki index.

## Table Ownership

| Table | Owner | Purpose |
|---|---|---|
| `users` | Laravel starter kit | Identity/authentication source of truth |
| Spatie permission tables | AccessControl | Role, permission, assignment persistence |
| `audit_logs` | AuditLog | Append-only security activity |
| `system_settings` | SystemSetting | Global runtime settings |
| `idempotency_keys` | API/SystemSetting | Duplicate request protection |
| `impersonation_sessions` | UserManagement | Impersonation lifecycle |

## Users and AccessControl

`users` tetap milik starter kit. `UserManagement` mengelola lifecycle di atas
identity tersebut dan tidak membuat tabel user kedua.

Schema role/permission memakai package Spatie sebagai persistence utama.
AccessControl menyediakan service, policy, contract, API, dan audit boundary
tanpa membuat schema role/permission duplikat. Role `Super System` dibuat oleh
initialization/seeder.

### Migration ULID Helper

Semua migration wajib menggunakan pola standar:

```php
$table->ulid('id')->primary();
$table->foreignUlid('user_id')->constrained('users');
```

Generator, model, factory, seeder, dan test wajib memakai pola yang sama.

## `audit_logs`

Custom append-only table tanpa `updated_at` dan `deleted_at`.

| Column | Rule |
|---|---|
| `id` | ULID primary key |
| `actor_id` | Nullable ULID FK/index |
| `action` | String/index |
| `subject_type` | Nullable string |
| `subject_id` | Nullable ULID |
| `module` | String/index |
| `project_id` | Nullable ULID/index |
| `tenant_id` | Nullable ULID/index untuk future scope |
| `correlation_id` | ULID/index |
| `reason` | Nullable text untuk impersonation/SystemSetting |
| `metadata` | Filtered JSONB |
| `created_at` | Event timestamp |

Audit record menyimpan actor, action, subject, timestamp, correlation ID, dan
filtered metadata. Secret, token, password, credential, dan sensitive payload
wajib di-redact. Retention minimal satu tahun. Auditor non-`Super System` dibatasi
oleh server-side scope policy; `Super System` dapat membaca seluruhnya.

Referential action `audit_logs.actor_id` menggunakan `SET NULL` agar histori tetap
ada setelah user soft delete. Audit log tidak boleh memakai cascade delete.

## `system_settings`

Global key-value settings dengan schema validation.

| Column | Rule |
|---|---|
| `id` | ULID primary key |
| `key` | Unique string |
| `value` | JSONB typed value |
| `type` | Schema type |
| `description` | Human/AI-readable purpose |
| `is_sensitive` | Boolean exposure control |
| `updated_by` | ULID FK ke `users` |
| `created_at`, `updated_at` | Timestamps |

Hanya `Super System` yang dapat mengubah setting. Perubahan langsung aktif
setelah validation dan mencatat before/after, actor, reason, timestamp,
correlation ID, dan audit event. Setting awal mencakup rate limit global,
idempotency retention/payload hash, idle timeout 30 menit, dan absolute session
lifetime 12 jam. Secret tidak disimpan sebagai plain value; invalid/unavailable
setting memakai safe default.

## `idempotency_keys`

| Column | Rule |
|---|---|
| `id` | ULID primary key |
| `actor_id` | ULID FK/index |
| `key` | Client key |
| `endpoint` | Normalized endpoint |
| `payload_hash` | Request payload hash |
| `response_status` | HTTP status |
| `response_body` | Sanitized JSONB replay response |
| `expires_at` | Default 24 hours/index |
| `created_at` | Timestamp |

Unique constraint: `actor_id + endpoint + key`. Key yang sama dengan payload
berbeda menghasilkan conflict. Expired record dapat dipurge sesuai policy.

## `impersonation_sessions`

| Column | Rule |
|---|---|
| `id` | ULID primary key |
| `actor_id` | ULID FK/index |
| `target_user_id` | ULID FK/index |
| `reason` | Required text |
| `status` | active, ended, expired, terminated |
| `started_at` | Timestamp |
| `ended_at` | Nullable timestamp |
| `correlation_id` | ULID/index |
| `metadata` | Filtered JSONB |
| `created_at`, `updated_at` | Timestamps |

Target `Super System` selalu ditolak. Satu actor tidak memiliki dua active
impersonation tanpa policy. Explicit exit dan force termination menghasilkan
audit event.

`impersonation_sessions.actor_id` mempertahankan referensi actor asli dan tidak
dihapus cascade. `target_user_id` dapat menjadi nullable dengan `SET NULL` setelah
session selesai, sementara histori audit tetap tersimpan.

## Migration and Integrity Rules

- Satu migration untuk satu perubahan terukur.
- Migration production tidak diubah; buat migration baru.
- Foreign key, index, unique constraint, dan referential action eksplisit.
- Destructive change memakai expand-and-contract serta rollback plan.
- Migration harus lulus pada database kosong dan upgrade database.
- Soft delete dipakai untuk entity yang membutuhkan histori; audit dan
  idempotency mengikuti retention policy, bukan soft delete.
- Assignment pivot role/permission mengikuti cascade sesuai schema Spatie.
- Referential action data bisnis ditentukan oleh owner module dan tidak boleh
  menghapus histori audit secara cascade.

## Encryption at Rest

- Database disk, backup, dan production storage wajib terenkripsi.
- Field-level encryption digunakan untuk integration secret, API token, refresh
  token, external credential, encryption material, dan PII berisiko tinggi bila
  disimpan.
- ULID, status, role, permission, timestamp, module, dan correlation ID tidak
  perlu field-level encryption.
- Password menggunakan hashing, bukan encryption.
- Encryption key berada di environment/secret manager, bukan plain database value.

## Audit Partition and Archive Trigger

Baseline memakai satu tabel `audit_logs`. Evaluasi partition/archive dilakukan
ketika salah satu kondisi tercapai:

- lebih dari 10 juta record;
- ukuran tabel melebihi 20–30 GB;
- query audit P95 melewati target;
- backup/restore mengganggu maintenance window;
- volume meningkat konsisten lebih dari 1 juta record per bulan.

Strategi lanjutan menggunakan monthly partition berdasarkan `created_at` dan
archive terenkripsi. Purge hanya boleh dilakukan setelah retention policy dan
operational approval tersedia.
