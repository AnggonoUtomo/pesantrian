## Security Principles

- Least privilege sebagai default.
- Explicit authorization pada server-side boundary.
- Deny by absence: hanya allow permission yang disimpan; tidak ada explicit deny model.
- Defense in depth melalui authentication, permission, policy, validation, dan audit.
- Actor asli tidak boleh hilang dari audit context.
- Secret tidak boleh berada di source code, log, response, atau plain SystemSetting.
- Security-sensitive action harus dapat diverifikasi dan ditelusuri.

## Authentication Boundary

Authentication menggunakan Laravel React starter kit dan tidak dibangun ulang
oleh baseline. Baseline mengintegrasikan user identity, session, auth middleware,
CSRF, dan password hashing sesuai contract starter kit.

- Password wajib menggunakan Laravel Hash.
- Session memakai secure cookie configuration sesuai environment.
- Idle session timeout dan absolute session lifetime dikelola melalui global
  `SystemSetting`; default baseline: idle 30 menit dan absolute 12 jam.
- Logout dan session invalidation mengikuti starter kit.
- Authentication flow bukan bagian dari AccessControl permission model.

## Authorization Model

Authorization memakai kombinasi role, allow permission, direct permission, policy,
dan guard.

- Role adalah kumpulan allow permission.
- User dapat memiliki optional direct allow permission.
- Policy rule membatasi action berdasarkan resource/state/context.
- Tidak ada tabel atau model explicit deny pada baseline.
- Permission key harus stabil dan terdokumentasi.
- Authorization diperiksa di route/API boundary dan use case boundary.

### Standard Module Authorization Pattern

Semua module menggunakan pola authorization yang sama:

```text
Authentication
  -> Controller/Route Middleware
  -> Policy/Gate
  -> AccessControl public capability
  -> Spatie Permission adapter
  -> Resource/state rule
  -> Audit bila mutation atau event sensitif
```

Controller module boleh mendeklarasikan middleware `can:*` untuk coarse-grained
authorization. Policy tetap dimiliki module pemilik resource dan wajib dipakai
untuk ownership, scope, state, atau resource-specific rule. Backend adalah
authority; middleware, policy, dan use-case authorization tidak boleh digantikan
oleh pemeriksaan frontend.

Permission identity tetap didefinisikan oleh module owner melalui
`permissions.php`. AccessControl menyediakan resolver, role/permission adapter,
public capability, dan integrasi Spatie Permission. Cross-module authorization
wajib memakai public contract, capability, DTO, atau public event.

Frontend Inertia boleh menerima typed `auth.authorization` context yang scoped,
misalnya `abilities`, `roles`, dan `isSuperSystem`, untuk visibility dan UX.
Context tersebut tidak menjadi security boundary. Permission privileged tidak
boleh dikirim kepada user yang tidak berhak.
- Filter UI tidak pernah menjadi security control.

## SuperSystem Role

`SuperSystem` adalah privileged baseline role yang dibuat melalui AccessControl
initialization/seeder. Role ini tidak diimplementasikan sebagai hardcoded bypass
di setiap feature.

- Full access diberikan melalui `SuperSystemPolicy` atau guard khusus.
- Full access mencakup role, permission, assignment, SystemSetting, dan audit log.
- Semua action `SuperSystem` tetap menghasilkan audit event.
- Role dan permission privileged tidak ditampilkan kepada user non-`SuperSystem`.
- Project turunan dapat membuat `Super Admin` tanpa otomatis memperoleh akses
  `SuperSystem`.

## User Impersonation

Impersonation adalah capability UserManagement yang dikontrol permission
`user.impersonate`; nama role tidak otomatis memberikan capability ini.

- Reason wajib dikumpulkan sebelum session dimulai.
- Session menyimpan actor asli dan target user secara terpisah.
- Audit mencatat actor, target, start, end/exit, reason, dan correlation ID.
- Impersonation tidak mengubah password, permission, role, atau identity actor.
- User `SuperSystem` selalu dilarang menjadi target impersonation.
- UI dan API menampilkan indicator impersonation.
- Explicit exit wajib tersedia dan tidak bergantung pada logout target.
- Semua action selama impersonation dapat ditelusuri ke actor asli dan target.

## Audit Log Security

Audit log bersifat append-only untuk security-sensitive action.

### Mandatory Events

- Create/update/deactivate/soft delete user.
- Assign/revoke role.
- Assign/revoke direct permission.
- Create/update/deactivate role atau permission.
- Start/action/end impersonation.
- Perubahan SystemSetting.
- Authorization denial penting dan akses audit di luar scope.

### Record Rules

- Wajib menyimpan actor, action, subject, timestamp, correlation ID, dan filtered metadata.
- Reason impersonation dan SystemSetting disimpan bila relevan.
- Secret, token, credential, password, dan payload sensitif wajib di-redact.
- Retention minimal satu tahun.
- Purge/archive wajib memiliki policy, authorization, dan operational audit.

## Audit Visibility

- Auditor non-`SuperSystem` hanya membaca record sesuai scope policy.
- `SuperSystem` dapat membaca seluruh audit log melalui guard/policy khusus.
- Scope dapat berupa module, project, tenant, atau resource ketika modelnya tersedia.
- Authorization scope wajib diverifikasi server-side.
- Resource di luar scope dapat merespons `404` untuk mencegah disclosure.

## SystemSetting Security

- Setting berlaku global pada baseline pertama.
- Hanya `SuperSystem` yang boleh mengubah setting.
- Perubahan langsung aktif setelah schema dan value validation berhasil.
- Baseline menggunakan audit-only; belum ada approval workflow.
- Audit mencatat actor, key, nilai sebelum/sesudah, reason, timestamp,
  correlation ID, dan result.
- Secret tidak boleh disimpan sebagai plain setting.
- Default aman digunakan bila setting invalid atau storage tidak tersedia.

## API and Session Controls

- Internal API memakai authorization server-side dan rate limit per actor.
- Rate limit dikonfigurasi melalui SystemSetting.
- Idempotency key dan response disimpan 24 jam dengan payload hash.
- CSRF aktif untuk session-based web request.
- Session impersonation memiliki explicit exit dan actor traceability.
- Error response tidak membocorkan stack trace, secret, atau existence resource
  di luar scope.

## Input, Output, and Data Protection

- Semua input menggunakan Form Request atau equivalent contract.
- Output di-escape untuk mencegah XSS.
- Query memakai Eloquent/query binding; raw query wajib direview.
- Upload memakai Spatie Media Library dengan MIME, size, extension, dan storage
  validation.
- Semua table identifier menggunakan ULID.
- Sensitive data tidak masuk log tanpa redaction.

## Package and Dependency Security

- Wayfinder dan Laravel Boost forbidden pada dependency, source, config, dan output.
- Package Spatie hanya digunakan sesuai approved package list.
- Dependency scan wajib berjalan pada CI.
- Perubahan package security-sensitive memerlukan review dan changelog.

## Security Scanning

- GitHub CodeQL digunakan untuk SAST pada JavaScript dan TypeScript. CodeQL
  tidak menyediakan language support PHP.
- PHP diperiksa melalui PHPStan/Larastan, Pest authorization dan security test,
  coverage gate, serta Composer audit.
- OWASP Dependency-Check digunakan untuk mendeteksi dependency dengan known
  vulnerabilities dan memblokir CVSS 7 atau lebih tinggi.
- SARIF CodeQL dengan `security-severity` minimal 7 atau level `error`
  memblokir merge.
- CI dapat menambahkan secret scanning dan dependency alert dari Git provider.

## Encryption at Rest

- Production wajib menggunakan HTTPS/TLS untuk data in transit.
- Database disk, backup, dan storage production wajib terenkripsi.
- Field sensitif tertentu menggunakan Laravel encrypted cast setelah daftar field
  ditetapkan oleh module.
- Password menggunakan hashing, bukan encryption.
- Secret, token, credential, dan password tidak boleh masuk audit log.
- Encryption key dikelola melalui environment atau secret manager, bukan source
  code atau plain SystemSetting.

## Security Headers and Transport

Environment production wajib mengaktifkan HTTPS dan security headers sesuai
deployment capability, minimal CSP, HSTS, X-Frame-Options, dan
X-Content-Type-Options.

## Security Verification

- Unit test untuk policy, permission resolver, redaction, dan validation.
- Feature test untuk unauthorized/forbidden/scope behavior.
- Integration test untuk session, impersonation, audit, storage, dan queue.
- Dependency scan untuk forbidden package.
- Manual review untuk SuperSystem, audit visibility, dan SystemSetting.
- Incident/recovery procedure diverifikasi pada staging.
