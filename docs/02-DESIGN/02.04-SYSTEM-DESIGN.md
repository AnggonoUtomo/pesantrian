## System Context

System terdiri dari Laravel React starter kit sebagai application foundation,
`app/Modules` sebagai bisnis/system module boundary, dan satu package
`packages/StarterKit` sebagai reusable framework/generator layer.

```text
Developer / AI
      |
      v
Module Console + Generator
      |
      v
packages/StarterKit
      |
      v
Laravel Application
      |
      +--> app/Modules/System/{Submodule}
      +--> Laravel React Starter Kit
      +--> PostgreSQL / Redis / Storage
```

## Technology Stack

- PHP 8.4+ and Laravel 13.
- Laravel React starter kit with Inertia, React, TypeScript, Vite.
- Tailwind CSS and shadcn/ui.
- PostgreSQL, Redis cache, Redis queue.
- Ziggy for frontend route integration.
- Spatie Permission and Spatie Media Library where approved.
- Wayfinder and Laravel Boost are prohibited.

## Architecture Style

- DDD-lite Modular Monolith.
- Domain-driven module boundaries.
- Contract/port-based dependency direction.
- Event-driven communication for meaningful state changes.
- Framework/kernel orchestration separate from business logic.
- One database/schema baseline with table ownership per module.

## Layer Architecture

```text
Presentation
    |
    v
Application
    |
    v
Domain
    |
    v
Infrastructure
```

### Presentation

Controller, Form Request, API Resource, Inertia page, command, and route. Tidak
boleh menampung business rule atau query persistence kompleks.

### Application

Use case, Action, application service, DTO, command handler, transaction
orchestration, authorization invocation, dan event dispatch coordination.

### Domain

Entity, value object, aggregate, domain service, domain event, port, dan contract.
Domain tidak bergantung pada Eloquent, HTTP, filesystem, queue vendor, atau UI.

### Infrastructure

Eloquent model, repository implementation, migration, external adapter, cache,
queue adapter, filesystem, provider, dan framework integration.

## Framework Package Boundary

`packages/StarterKit` menjadi boundary awal untuk:

- module manifest schema;
- module registry dan discovery;
- generator dan stub engine;
- module console;
- lifecycle/bootstrap contract;
- shared filesystem, cache, and diagnostic service;
- framework configuration and package policy.

Package tidak memiliki business logic `AccessControl`, `UserManagement`,
`AuditLog`, atau `SystemSetting`; package hanya menyediakan framework capability.

### Composer Development Boundary

Development monorepo menggunakan Composer path repository:

```json
{
  "repositories": [
    { "type": "path", "url": "packages/StarterKit" }
  ]
}
```

Internal Git/Composer distribution digunakan saat package dirilis untuk project
turunan.

## Dependency Rules

- Presentation boleh bergantung ke Application contract.
- Application boleh bergantung ke Domain contract.
- Domain tidak bergantung ke Infrastructure atau framework concrete class.
- Infrastructure mengimplementasikan Domain/Application port.
- Module tidak mengakses private implementation module lain secara langsung.
- Cross-module call wajib memakai public contract melalui communication layer
  module atau domain/integration event.
- Direct concrete dependency lintas module dilarang.
- Direct dependency hanya boleh untuk public event atau shared value object yang
  sudah disepakati.
- Setiap module memiliki layer komunikasi sendiri untuk request, contract, event,
  mapping, dan authorization boundary.
- Module tidak boleh mengambil alih communication layer module lain.
- Shared code hanya dibuat jika benar-benar cross-cutting dan memiliki owner.
- Dependency antar-module ditulis dalam `module.json`.
- Permission identity dan metadata permission didefinisikan oleh module owner
  pada `permissions.php`.
- AccessControl melakukan discovery dan sync permission dari module valid tanpa
  memindahkan ownership definisi ke AccessControl.
- Semua module memakai standard authorization pattern: controller middleware
  untuk coarse-grained check, policy/gate untuk resource dan state rule, lalu
  AccessControl public capability sebagai cross-module boundary. Inertia shared
  authorization data hanya untuk frontend UX; backend tetap authoritative.

## Request Flow

```text
HTTP/Command
  -> Route/Controller/Command
  -> Form Request / Input DTO
  -> Authorization Policy/Permission
  -> Application Action/Use Case
  -> Domain Entity/Service + Contract
  -> Infrastructure Adapter/Repository
  -> Domain Event / Audit Event
  -> Resource/Presenter/Command Output
```

Model persistence tidak dikembalikan langsung sebagai API response.

## Event Flow

Domain event dipakai untuk state change bermakna dalam module. Integration event
dipakai hanya saat komunikasi melewati module boundary atau external system.

```text
Use Case
  -> Domain State Change
  -> Domain Event
  -> Event Bus
  -> Listener/Handler
  -> Audit / Queue / Integration Adapter
```

Event handler harus idempotent dan tidak menjadi pengganti contract synchronous
untuk operasi yang membutuhkan immediate result.

## System Module Responsibilities

| Module | Responsibility |
|---|---|
| AccessControl | Role, permission, assignment, policy, guard, Super System |
| UserManagement | User lifecycle, soft delete, impersonation |
| AuditLog | Append-only security records, scope, retention |
| SystemSetting | Global validated runtime settings, rate limit, idempotency, session timeout, recovery targets |

Auth, profile, notification, dan settings starter kit tetap menjadi integration
dependency bila capability tersebut sudah tersedia secara default.

## Cross-Cutting Controls

- ULID seluruh primary/foreign key.
- Correlation ID pada request, event, audit, dan idempotency.
- Rate limit per actor melalui SystemSetting.
- Idempotency key 24 jam dengan payload hash.
- Audit event untuk security-sensitive action.
- `Super System` policy/guard khusus.
- Forbidden dependency scan untuk Wayfinder dan Laravel Boost.

## Failure Handling

- Validation error menjadi `422` dengan error code konsisten.
- Authorization denial menjadi `403` atau `404` sesuai disclosure policy.
- Domain error dipetakan ke application error tanpa membocorkan detail internal.
- Infrastructure failure dicatat dengan correlation ID dan safe response.
- Module invalid diisolasi saat discovery; CI/validate command tetap failure.
- Event handler failure mengikuti retry/dead-letter policy.
- Tidak ada fallback yang menyembunyikan data corruption atau security denial.

## Naming and Contract Examples

```text
CreateUserAction
UserRepositoryContract
EloquentUserRepository
UserCreated
RecordUserCreatedAudit
SuperSystemPolicy
```

Contract/interface berada pada boundary yang membutuhkan substitusi; jangan
membuat interface tanpa consumer atau alasan architectural yang jelas.

## Correlation and Communication Identity

- `correlation_id` menggunakan ULID dan merepresentasikan satu alur request/bisnis.
- `job_id` menggunakan ULID dan merepresentasikan satu eksekusi asynchronous job.
- `actor_id` menggunakan ULID dan merepresentasikan actor pemicu action.
- Job wajib membawa `correlation_id`, `job_id`, dan actor context bila tersedia.
- Audit, event, log, dan response metadata menggunakan correlation ID yang sama.

## Observability

Minimal setiap request/action penting dapat ditelusuri melalui:

- correlation ID;
- actor ID dan impersonation context bila ada;
- module dan action name;
- structured log level;
- audit event untuk security-sensitive action;
- duration dan outcome tanpa sensitive payload.

## Test Architecture

- Domain unit test untuk rule dan value object.
- Application feature test untuk use case dan authorization.
- Infrastructure integration test untuk PostgreSQL, Redis, filesystem, queue.
- Contract test untuk module boundary dan generator output.
- Browser/smoke test untuk critical user journey.
