## UI Stack

- React and TypeScript.
- Inertia.js.
- Vite.
- Tailwind CSS.
- shadcn/ui sebagai component foundation.
- Lucide Icons.
- React Hook Form dan Zod bila form membutuhkan state/validation kompleks.

## Design Principles

- Clear: user selalu memahami status, action, dan consequence.
- Consistent: gunakan shadcn/ui dan shared component sebelum membuat custom component.
- Accessible: target WCAG 2.2 Level AA.
- Responsive: critical flow usable pada supported viewport.
- Secure by default: jangan menampilkan capability atau data di luar authorization scope.
- Recoverable: destructive action memiliki confirmation dan feedback.
- Traceable: impersonation dan security-sensitive action terlihat jelas.
- AI-readable: page, component, type, dan permission naming konsisten.

Page module tidak boleh mengimpor private implementation module lain. Shared
component berada pada `resources/js/components/ui` atau `resources/js/components/shared`.
Module-specific component wajib berada di folder module terkait, bukan di shared
folder global.

## Layout

Starter kit memakai layout reusable:

- `AppLayout`: authenticated application shell.
- `GuestLayout`: unauthenticated flow.
- `SettingsLayout`: user settings dari starter kit.
- `SystemLayout`: navigation dan context System module.
- `AuditLayout`: scoped audit browsing dan security indicator.

Layout wajib memiliki skip link, landmarks, responsive navigation, focus state,
dan error boundary.

## Component Rules

- Reuse shadcn/ui sebelum membuat primitive baru.
- Setiap interactive component memiliki keyboard behavior.
- Setiap input memiliki label, description/error, dan accessible name.
- Button menjelaskan action; jangan memakai label ambigu seperti `Submit` bila
  konteks dapat dibuat spesifik.
- Destructive action memakai confirmation dan menjelaskan impact.
- Loading state, empty state, error state, dan success feedback wajib tersedia.
- Modal tidak boleh menjadi satu-satunya tempat informasi penting.
- Jangan mengandalkan warna saja untuk menyampaikan status.

## Page Contract

Page module menggunakan struktur:

```text
resources/js/pages/System/AccessControl/
|-- pages/
|   |-- Index.tsx
|   |-- Create.tsx
|   |-- Edit.tsx
|   `-- Show.tsx
|-- components/
|-- schemas.ts
|-- types.ts
`-- index.ts
```

Page menerima typed props dari Inertia/API resource dan tidak menempatkan
business rule atau authorization decision di frontend. Frontend hanya mengatur
presentation; server tetap menjadi authority.

## Component Ownership

- `resources/js/components/ui`: primitive shadcn/ui dan UI foundation.
- `resources/js/components/shared`: component reusable lintas module.
- `pages/System/{Module}/components`: component khusus module.
- `pages/System/{Module}/pages`: page entry point module.
- Component module tidak boleh dipindah ke shared hanya untuk menghindari
  import path; pindahkan hanya jika benar-benar dipakai lintas module.
- Gunakan folder `components`, bukan nama folder dengan hyphen seperti
  `AccessControl-Component`, agar mengikuti konvensi frontend dan import path.

## Permission-aware UI

- Navigation dan action di-hide/disable berdasarkan capability yang dikirim
  server, tetapi server authorization tetap wajib.
- Role/permission `SuperSystem` tidak ditampilkan kepada user non-
  `SuperSystem`.
- SystemSetting hanya tampil dan dapat diubah oleh `SuperSystem`.
- Audit log hanya menampilkan record sesuai scope auditor.
- Error `403` memiliki feedback yang aman tanpa membocorkan detail permission.

## Impersonation UX

Saat impersonating:

- Persistent banner/indicator wajib terlihat pada seluruh authenticated layout.
- Indicator menampilkan target user dan actor asli secara aman.
- Start flow mewajibkan reason.
- Exit action selalu tersedia dan mudah ditemukan.
- Jangan menampilkan secret, credential, atau permission internal pada banner.
- Target `SuperSystem` tidak boleh muncul sebagai target eligible.

## Forms

- Gunakan controlled/typed form sesuai kompleksitas.
- Validasi client hanya untuk feedback; server validation tetap authority.
- Error field ditampilkan dekat input dan diringkas pada error summary.
- Preserve input yang aman setelah validation failure.
- Sensitive input tidak dipersist ke local storage atau analytics.
- Setting value JSONB ditampilkan melalui form schema yang typed, bukan editor
  bebas tanpa validation.

## Tables and Audit Views

- Table mendukung loading, empty, error, pagination, filter, search, dan sort.
- Pagination mengikuti API contract `page`, `per_page`, `search`, `sort`, dan
  `filter[...]`.
- Bulk action wajib memeriksa capability dan confirmation.
- Audit table menampilkan actor, action, subject, module, timestamp, dan
  correlation ID; metadata sensitif tidak ditampilkan.
- Scope filter bukan security control; server tetap memfilter.

## Feedback and Error Handling

- Success memakai toast/banner yang tidak mengganggu keyboard focus.
- Error API menggunakan `code` dan message yang dapat ditindaklanjuti.
- Unexpected error memakai safe message dan correlation ID untuk support.
- Forbidden/404 tidak membocorkan resource yang berada di luar scope.
- Network retry tidak boleh menggandakan side effect; gunakan idempotency key.

## Accessibility WCAG 2.2 AA

- Semua critical flow dapat dijalankan dengan keyboard.
- Focus visible dan focus order logis.
- Kontras warna memenuhi AA.
- Heading dan landmark semantic.
- Form label, error, status, dan live region accessible.
- Dialog memiliki focus trap dan close behavior yang benar.
- Motion dapat dikurangi melalui preference.
- Automated accessibility scan dilengkapi manual keyboard review.

## Responsive and Browser Support

Support versi terbaru dan satu versi sebelumnya untuk Chrome, Edge, Firefox,
dan Safari. Mobile wajib usable untuk critical read flow dan action sederhana;
create/edit kompleks tetap diprioritaskan pada desktop.

## Theme, Design Token, and Branding

Design token dan branding dikonfigurasi melalui global `SystemSetting`, bukan
hardcode di component. Setting dikelola oleh `SuperSystem`, tervalidasi, dan
setiap perubahan menghasilkan audit event.

Konfigurasi baseline mencakup nama aplikasi, logo placeholder, favicon, pilihan
theme warna, warna netral/semantic, typography default, light theme, dark theme,
dan system preference. Component hanya menggunakan design token sehingga project
turunan dapat mengganti branding tanpa mengubah source component.

## Naming

- Component dan type: PascalCase.
- Function, hook, variable: camelCase.
- Hook diawali `use`.
- Page mengikuti route/module vocabulary.
- Permission key memakai dot notation, misalnya `user.impersonate`.
- Test memakai nama behavior yang diverifikasi.

## UI Verification

- Component test untuk state dan keyboard behavior.
- Feature/browser test untuk critical flow.
- Accessibility scan dan manual keyboard review.
- Visual review untuk light/dark, responsive, loading, empty, error, dan
  impersonation state.
- Permission visibility test untuk SuperSystem, auditor scope, dan SystemSetting.
- Playwright untuk end-to-end browser testing.
- axe-core untuk automated accessibility scan.
- Chrome DevTools MCP untuk runtime DOM, console, network, dan visual debugging.
- Lighthouse sebagai audit tambahan untuk performance dan accessibility.
- Manual keyboard review untuk critical flow.
