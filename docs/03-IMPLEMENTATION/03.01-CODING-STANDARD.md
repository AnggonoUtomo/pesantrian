## General Rules

- Code harus readable, explicit, testable, dan mengikuti boundary module.
- Hindari clever abstraction yang tidak memiliki consumer jelas.
- Satu class/function memiliki satu responsibility yang dapat dijelaskan.
- Business rule ditempatkan pada Domain/Application, bukan Controller atau UI.
- Semua perubahan behavior memiliki test dan update dokumentasi bila contract berubah.
- Jangan menambahkan dependency tanpa review package, security, dan maintenance impact.

## PHP

- Ikuti PSR-12 dan gunakan strict typing.
- Gunakan dependency injection melalui constructor atau method contract.
- Gunakan typed property, return type, parameter type, dan readonly bila sesuai.
- Hindari static helper, global state, magic string, dan hidden service locator.
- Gunakan exception yang bermakna dan map error pada application boundary.
- Jangan menaruh secret, token, atau credential dalam source code.

## Laravel

Gunakan:

- Form Request untuk input validation.
- Policy/Gate untuk authorization.
- API Resource/Presenter untuk response mapping.
- Action/Application Service untuk use case.
- Event dan Listener untuk meaningful state change.
- Queue untuk pekerjaan asynchronous.
- Eloquent melalui repository/infrastructure boundary.
- Config/environment untuk bootstrap config.

Hindari:

- Business logic di Controller, Model Eloquent, Blade, atau React Page.
- Query persistence langsung dari Controller atau frontend.
- Mengembalikan Eloquent model langsung sebagai API contract.
- Mengubah migration production yang sudah dirilis.
- Menyimpan secret pada SystemSetting plain value.

## DDD-lite Module Rules

Layer mengikuti:

```text
Presentation -> Application -> Domain <- Infrastructure
```

- Domain tidak bergantung pada Laravel, Eloquent, HTTP, queue vendor, atau UI.
- Infrastructure mengimplementasikan contract/port Domain atau Application.
- Cross-module dependency wajib memakai public contract dan communication layer.
- Direct concrete dependency lintas module dilarang.
- Pengecualian hanya public event atau shared value object yang disepakati.
- Setiap module memiliki contract, event, mapping, authorization, dan test boundary.
- Private implementation module tidak boleh diimport module lain.
- Module dependency wajib tercatat pada `module.json`.
- Permission identity module wajib didefinisikan pada `permissions.php` milik
  module menggunakan metadata `key`, `description`, `module`, dan `sensitive`,
  bukan tersebar di controller, seeder global, atau frontend.
- Module baru wajib dibuat melalui `php artisan module:make`; pembuatan manual
  membutuhkan exception ADR dan parity test dengan generator.
- Setiap module wajib memiliki README internal sebagai context dan operational
  guide.
- Setting module yang disimpan global tetap memiliki schema dan default di
  module pemilik; persistence dikelola melalui contract SystemSetting.

## Contract and Event

- Interface diberi nama berdasarkan capability, misalnya `PermissionChecker`.
- Contract hanya dibuat jika memiliki consumer/boundary nyata.
- Event menggunakan past tense, misalnya `UserCreated` atau `SettingUpdated`.
- Event payload typed dan tidak membawa secret/sensitive payload.
- Handler wajib idempotent bila dapat di-retry.
- Domain event untuk internal module; application event untuk koordinasi
  application layer; integration event untuk lintas module/external.
- Domain event tidak otomatis menjadi integration event.
- Integration event wajib memiliki event identity, version, timestamp,
  correlation ID ULID, dan payload yang sudah disanitasi.
- Correlation ID, job ID, dan actor ID menggunakan ULID bila event/queue
  workflow membutuhkannya.

## Application Execution Pattern

- Application Action adalah default untuk mutation synchronous.
- Application Query adalah default untuk read dan typed DTO/read contract.
- Command Bus, Queue/Job, Facade, dan Shared Kernel bukan default baseline.
- Baseline menggunakan CQRS-lite: Action untuk write dan Query untuk read,
  tanpa read database terpisah atau event sourcing.

Detail dan matriks status implementasi ada pada
`03.12-MODULE-COMMUNICATION-AND-EXECUTION.md`.

## Database and Identifier

- Semua model dan tabel menggunakan ULID.
- Primary key selalu `id`; foreign key memakai `{entity}_id`.
- Jangan membuat integer auto-increment atau UUID baru.
- Migration memakai:

```php
$table->ulid('id')->primary();
$table->foreignUlid('user_id')->constrained('users');
```

- Model, factory, seeder, DTO, route, event, policy, dan test konsisten memakai ULID.
- Table dan column memakai `snake_case`.
- Soft delete hanya untuk entity yang membutuhkan histori.

## Security Coding Rules

- Authorization selalu server-side; frontend visibility bukan security control.
- Permission baseline hanya allow permission dan policy rule.
- `SuperSystem` memakai policy/guard khusus, bukan bypass tersebar.
- Permission `user.impersonate` wajib untuk impersonation.
- Reason impersonation wajib dan target `SuperSystem` selalu ditolak.
- Semua security-sensitive action menghasilkan audit event.
- Audit metadata wajib di-redact dari secret, token, password, credential, dan PII sensitif.
- Rate limit dan idempotency menggunakan `SystemSetting`.
- Wayfinder dan Laravel Boost dilarang.

## React and TypeScript

- Gunakan functional component dan TypeScript strict typing.
- Hindari `any`; gunakan type guard atau type yang jelas.
- Gunakan custom hook untuk reusable state/behavior.
- Page hanya mengatur presentation/orchestration, bukan business rule.
- Gunakan typed props dan typed API/Inertia data.
- Form memakai schema validation bila kompleks; server tetap authority.
- Loading, empty, error, success, dan disabled state harus ditangani.
- Komponen interactive harus keyboard accessible.

## Frontend Ownership

```text
resources/js/components/ui       # shadcn/ui primitives
resources/js/components/shared   # reusable cross-module components
resources/js/pages/System/{Module}/components
                                  # module-specific components
resources/js/pages/System/{Module}/pages
                                  # module page entry points
```

Module-specific component tidak diletakkan pada global shared folder kecuali
benar-benar dipakai lintas module. Gunakan folder `components`, bukan nama
`Module-Component`.

## Baseline Visual Module

Module frontend mengikuti token dan komponen visual AccessControl:

- Light memakai putih bersih untuk topnav, sidebar, dan card utama. Subcard
  memakai abu-abu netral yang sedikit lebih gelap.
- Dark memakai palette aktif untuk topnav, sidebar, dan card utama. Subcard
  sedikit lebih gelap dari card utama.
- Accent hanya menjadi penanda icon, badge, border, garis card, hover, active,
  dan focus. Jangan menambahkan warna surface hardcode untuk module baru.
- Gunakan `dashboard-card`, `dashboard-subcard`, `dashboard-icon`, dan
  `dashboard-badge` jika jenis komponen sesuai.
- Verifikasi light/dark, responsive, accessibility, dan console browser.

## Naming Convention

| Target | Convention | Example |
|---|---|---|
| Class/component/type | PascalCase | `UserController`, `UserTable` |
| Method/function/variable | camelCase | `createUser`, `userId` |
| Constant | UPPER_SNAKE_CASE | `DEFAULT_TIMEOUT` |
| Table/column | snake_case | `audit_logs`, `actor_id` |
| Permission | dot notation | `user.impersonate` |
| Event | Past tense PascalCase | `UserCreated` |
| Migration | Laravel snake_case timestamp | `create_audit_logs_table` |
| Module | PascalCase | `AccessControl` |
| Command | Artisan colon syntax | `module:make` |

## Testing Standard

- Unit test untuk Domain rule, value object, policy, mapper, dan resolver.
- Feature test untuk use case, authorization, validation, dan API.
- Integration test untuk database, Redis, queue, storage, dan external adapter.
- Browser test untuk critical flow dan impersonation UX.
- Security test untuk scope, SuperSystem, forbidden dependency, redaction.
- Generated output wajib memiliki structure, conflict, dry-run, dan force test.
- Test harus deterministic dan tidak bergantung pada external service tanpa fake/contract.

## Formatting and Quality Gate

- Formatter dan static analysis wajib berjalan sebelum merge.
- CI wajib menjalankan test, dependency scan, forbidden dependency check, dan
  CodeQL/approved security scan.
- Pull request menyebutkan requirement, test, migration, security, dan deployment impact.
- Jangan commit debug output, generated secret, `.env`, atau credential.

### Approved Tools

PHP:

- Laravel Pint untuk formatting.
- PHPStan + Larastan untuk static analysis.
- Pest atau PHPUnit untuk testing.

TypeScript/React:

- Prettier untuk formatting.
- ESLint untuk lint dan React rules.
- `tsc --noEmit` untuk type checking.
- Vitest untuk unit/component test bila diperlukan.

### Coverage Threshold

| Layer | Minimum |
|---|---:|
| Domain rules/value object | 90% |
| Application/use case | 85% |
| Policy/security/authorization | 90% |
| Infrastructure/repository | 75% |
| API/feature critical flow | 80% |
| Generator/filesystem | 85% |
| React shared components | 80% |
| Browser/E2E | Critical flow verification, bukan angka coverage |

Coverage tidak menggantikan acceptance test. Security rule dan seluruh `Must`
requirement wajib memiliki verification meskipun angka coverage sudah tercapai.

### CI and Branch Protection

Baseline menggunakan GitHub Actions. Pipeline minimal wajib menjalankan install
dependency, forbidden dependency check, Pint, PHPStan/Larastan, Prettier, ESLint,
TypeScript check, unit/feature/integration/browser test, CodeQL, dependency scan,
coverage report, dan frontend build.

Branch `main` wajib protected:

- Direct push dilarang.
- Pull request wajib untuk semua perubahan.
- Minimal satu reviewer.
- Semua required CI check harus lulus.
- Unresolved conversation memblokir merge.
- Force push dan branch deletion dilarang.
- Critical security finding memblokir merge.
- CODEOWNERS digunakan untuk framework, kernel, security, dan deployment docs.

## Commit Message

Gunakan Conventional Commits:

```text
feat: add module generator validation
fix: prevent impersonation of super system
refactor: isolate permission contract
docs: update database design
test: cover audit scope policy
style: format module components
chore: update approved dependency
```
