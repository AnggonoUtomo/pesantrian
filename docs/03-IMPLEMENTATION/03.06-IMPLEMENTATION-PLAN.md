## Planning Principles

- Implementasi dimulai dari contract dan acceptance criteria.
- High-risk dependency dan security decision dikerjakan lebih awal.
- Setiap task memiliki owner, dependency, acceptance criteria, test impact, dan rollback impact.
- Setiap phase berakhir dengan working checkpoint.
- Task yang membutuhkan keputusan unresolved ditandai blocked, bukan ditebak.
- Auth, profile, notification, dan settings bawaan starter kit tidak dibangun ulang;
  `SystemSetting` adalah system runtime setting milik baseline.

## Phase 0 — Context and Specification

### Objective

Memastikan dokumentasi `00–07` menjadi baseline yang konsisten sebelum coding.

### Tasks

- Finalisasi scope, glossary, vision, dan baseline direction.
- Finalisasi functional/NFR/PRD/user story/baseline specification.
- Review system, database, security, API, dan UI design.
- Register Open Decisions dan owner-nya.
- Validasi traceability requirements → design → task → test.

### Exit Criteria

- Baseline requirement dan acceptance criteria disetujui.
- Tidak ada conflict scope yang tersembunyi.
- Developer, QA, dan DevOps dapat memahami Definition of Done.

## Phase 1 — Starter Foundation

### Objective

Membuat Laravel React starter kit terverifikasi dan aman sebagai application foundation.

### Tasks

- Install/verify PHP 8.4+ dan Laravel 13.
- Verify React starter kit, Inertia, TypeScript, Vite, Tailwind, shadcn/ui.
- Hapus Wayfinder dan Laravel Boost bila ada; pastikan tidak tersisa.
- Install/verify Ziggy, PostgreSQL, Redis, Spatie Permission, dan Media Library.
- Terapkan Composer path repository untuk `packages/StarterKit`.
- Verifikasi environment, ULID support, session, cache, queue, dan storage.

### Exit Criteria

- `starter:verify` lulus.
- Application boot dan frontend build lulus.
- Database, cache, queue, dan storage health lulus.
- Forbidden dependency scan lulus.

## Phase 2 — Framework Package and Module Contract

### Objective

Membangun boundary reusable `packages/StarterKit` dan contract module.

### Tasks

- Scaffold `packages/StarterKit` dengan Composer metadata.
- Implementasikan module manifest schema `module.json`.
- Implementasikan `module.php` runtime configuration contract.
- Implementasikan `permissions.php` module-local permission identity.
- Tetapkan module namespace, status, version, dependency, provider, dan path.
- Tetapkan communication layer, public contract, event, dan correlation ID.
- Tetapkan ULID migration/model/factory conventions.

### Exit Criteria

- Module contoh valid dapat di-register.
- Module invalid menghasilkan diagnostic.
- Cross-module concrete dependency dapat dideteksi.
- Contract test dan schema test lulus.

## Phase 3 — Generator and Module Console

### Objective

Membuat generator profile `default-v1` dan command `module:make` yang aman.

### Tasks

- Implementasikan `module:make` dengan profile `default-v1`.
- Generate DDD-lite folder, manifest, config, permission source kosong, provider,
  route entry point, dan README minimum.
- Implementasikan staging directory dan atomic promotion.
- Implementasikan conflict detection, `--dry-run`, `--force`, `--yes`, dan cleanup.
- Implementasikan `--json` output contract.
- Implementasikan `module:inspect`, `module:list`, `discover`, dan `validate`.
  `module:inspect` harus tersedia sebelum module business baru dibuat. `enable`
  dan `disable` tetap menjadi roadmap karena belum menjadi scope baseline.
- Implementasikan `starter:verify`, `starter:diagnose`, dan `starter:health`.
- Tambahkan generator snapshot, filesystem, failure, dan security tests.

### Exit Criteria

- `php artisan module:make AccessControl --domain=System --force --yes --json` lulus.
- Re-run tanpa `--force` tidak menimpa file.
- CI dapat menjalankan command dengan `--json`.
- `module:inspect` dapat membaca detail module existing tanpa side effect.
- Partial write tidak meninggalkan module setengah jadi.

## Phase 4 — Initial System Modules

### Objective

Menghasilkan vertical slice System yang usable.

### Module Order

1. `AccessControl` — role, permission, assignment, policy, guard, `SuperSystem`.
2. `UserManagement` — lifecycle user, soft delete, role integration, impersonation.
3. `AuditLog` — append-only record, redaction, scope, retention.
4. `SystemSetting` — global setting, rate limit, idempotency, session, branding/design token.

### Tasks

- Generate setiap module dengan profile `default-v1`.
- Tambahkan module-local `permissions.php`.
- Implementasikan migration, ULID, index, FK, seeder, factory, dan test.
- Integrasikan Spatie Permission pada AccessControl.
- Seed `SuperSystem` melalui initialization/seeder.
- Implementasikan `user.impersonate`, reason wajib, exit, dan target denial.
- Implementasikan audit event seluruh security-sensitive action.
- Implementasikan scoped audit visibility.
- Implementasikan SystemSetting global dengan validation, default, audit, dan safe fallback.
- Implementasikan branding/design token dan light/dark configuration.
- Untuk setiap module yang memiliki alur pengguna, buat frontend page/component
  pada increment module yang sama. Sertakan route Ziggy, state UI, permission
  visibility, responsive layout, dan browser/accessibility test.

### Exit Criteria

- Role/permission flow lulus.
- User lifecycle dan impersonation lulus.
- Audit log immutable, redacted, scoped, dan teruji.
- SystemSetting hanya dapat diubah `SuperSystem` dan langsung aktif setelah validation.
- Semua initial module memiliki frontend ownership, frontend vertical slice,
  dan browser verification sebelum module dinyatakan selesai.

## Phase 5 — Integration and Hardening

### Objective

Memastikan platform siap dipakai lintas project dan memenuhi NFR.

### Tasks

- Integrasikan API envelope, pagination, filter, sorting, dan idempotency.
- Integrasikan rate limit per actor.
- Implementasikan UI WCAG 2.2 AA dan impersonation indicator.
- Jalankan unit, feature, integration, browser, accessibility, dan performance test.
- Jalankan PHP/TypeScript formatter, static analysis, CodeQL, dependency scan.
- Benchmark 100 concurrent users dan dataset sampai 100.000 record.
- Review encryption-at-rest, secret handling, audit redaction, dan session timeout.

### Exit Criteria

- Availability/performance baseline memiliki evidence.
- Critical security finding tertutup.
- Browser support matrix lulus.
- Coverage threshold dan seluruh Must requirement terpenuhi.

## Phase 6 — CI/CD and Release

### Objective

Menjadikan baseline dapat dirilis, diulang, di-rollback, dan dioperasikan.

### Tasks

- Implementasikan GitHub Actions pipeline.
- Aktifkan protected `main`, PR review, CODEOWNERS, dan required checks.
- Tambahkan environment contract dan secret management.
- Tambahkan migration deployment, backup, restore, dan rollback.
- Tambahkan staging smoke test, observability, dan incident procedure.
- Update changelog, release note, known issues, dan version.

### Exit Criteria

- Clean machine quickstart berhasil.
- Staging deployment dan rollback drill berhasil.
- Restore drill berhasil.
- CI seluruhnya hijau.
- Release owner menyetujui baseline.

## Definition of Done Per Task

- Requirement/acceptance criteria tertaut.
- Code mengikuti coding standard dan ownership module.
- Test atau verification evidence tersedia.
- Security, migration, performance, dan deployment impact direview.
- Dokumentasi terkait diperbarui.
- Tidak ada secret atau forbidden dependency.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Generator menimpa code manual | High | Fail-safe, dry-run, confirmation, staging promotion |
| Module coupling | High | Contract-first communication layer dan architecture test |
| Audit data bocor | High | Redaction, scope policy, encryption/storage controls |
| Starter kit berubah | Medium | Verification matrix dan compatibility policy |
| Scope melebar | High | Vertical slice, phase gate, dan ADR |
