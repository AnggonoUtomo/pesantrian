## Module Definition

Module adalah boundary domain/system yang memiliki identity, owner, contract,
dependency, permission identity, lifecycle, migration, test, dan dokumentasi.
Module bukan sekadar folder teknis dan tidak boleh menjadi tempat business logic
yang tidak memiliki owner.

Setiap module wajib memiliki `README.md` internal yang menjelaskan purpose,
boundary, public contract, permission, event, dependency, konfigurasi, cara
menjalankan test, dan operational notes. README ini menjadi context pack minimum
untuk developer dan AI coding assistant.

## Module Taxonomy

```text
app/Modules/
|-- System/
|   |-- AccessControl/
|   |-- UserManagement/
|   |-- AuditLog/
|   `-- SystemSetting/
`-- {BusinessDomain}/
    `-- {Submodule}/
```

`System` adalah parent module untuk capability cross-cutting baseline.
Business domain project turunan berada pada parent domain masing-masing dan tidak
boleh menyimpan business logic di System tanpa alasan yang disetujui.

Authentication, profile, notification, dan settings default tetap menjadi
capability starter kit. `SystemSetting` adalah runtime configuration module dan
bukan pengganti settings UI bawaan starter kit.

## Initial System Modules

### AccessControl (Baseline Module Pertama)

Owner untuk role, permission, assignment, policy, guard, effective allow, dan
`SuperSystem`.

- Menggunakan schema Spatie Permission sebagai persistence utama.
- Tidak memiliki explicit deny model.
- Discover/sync permission identity dari module lain.
- Menyediakan public contract `PermissionChecker`/capability equivalent.
- Role dan permission privileged hanya terlihat bagi pemegang `SuperSystem`.

### UserManagement

UserManagement adalah module business pertama setelah AccessControl contract
tersedia. Module ini menggunakan authentication starter kit yang sudah ada,
memiliki public contract untuk lifecycle user, dan mengonsumsi capability
otorisasi melalui public contract AccessControl. Generator tidak boleh membuat
authorization implementation kedua di dalam UserManagement.

### UserManagement Integration Rules

Owner untuk lifecycle user di atas tabel `users` starter kit.

- Create, read, update, active/inactive, soft delete.
- Role assignment melalui AccessControl contract.
- Impersonation melalui permission `user.impersonate`.
- Reason impersonation wajib.
- Target `SuperSystem` selalu ditolak.
- Session actor asli dan target disimpan terpisah.

### AuditLog

Owner untuk audit record append-only dan visibility scope.

- Menyimpan actor, action, subject, module, correlation ID, reason, dan filtered metadata.
- Auditor non-`SuperSystem` hanya melihat scope yang diizinkan.
- Retention minimal satu tahun.
- Tidak menyimpan secret, token, password, credential, atau sensitive payload.
- Menyediakan public audit recording contract untuk module lain.

### SystemSetting

Owner untuk global runtime setting tervalidasi.

- Hanya `SuperSystem` yang dapat mengubah setting.
- Perubahan langsung aktif setelah validation dan wajib diaudit.
- Rate limit per actor/endpoint.
- Idempotency retention 24 jam dan payload hash.
- Idle timeout 30 menit dan absolute session lifetime 12 jam.
- Branding/design token, nama aplikasi, logo, favicon, theme, typography, dan light/dark preference.
- Operational recovery target: `operations.rto_hours` dan `operations.rpo_hours`.
- Secret tidak boleh disimpan sebagai plain value.

SystemSetting boleh menyimpan runtime setting module lain sebagai storage global.
Definisi key, schema, default, validasi, dan perilaku setting tetap dimiliki
module asal. Module asal mendaftarkan setting melalui contract SystemSetting;
SystemSetting mengelola persistence, authorization, activation, cache, dan audit.

## Module Manifest

Minimal `module.json`:

```json
{
  "name": "AccessControl",
  "namespace": "App\\Modules\\System\\AccessControl",
  "domain": "System",
  "version": "1.0.0",
  "schema_version": 1,
  "status": "enabled",
  "path": "app/Modules/System/AccessControl",
  "provider": "App\\Modules\\System\\AccessControl\\ServiceProvider",
  "dependencies": [],
  "permission_source": "permissions.php",
  "config_source": "module.php"
}
```

Manifest menjadi input discovery/registry dan wajib schema-valid.

## Permission Identity

Setiap module mendefinisikan permission di `permissions.php` miliknya.

Contoh `AccessControl/permissions.php`:

```php
return [
    [
        'key' => 'access_control.role.manage',
        'description' => 'Manage roles',
        'module' => 'AccessControl',
        'sensitive' => false,
    ],
    [
        'key' => 'access_control.permission.manage',
        'description' => 'Manage permissions',
        'module' => 'AccessControl',
        'sensitive' => true,
    ],
]; 
```

Semua module menggunakan schema metadata yang sama. Contoh permission module
lain:

```php
return [
    [
        'key' => 'user.impersonate',
        'description' => 'Impersonate a user',
        'module' => 'UserManagement',
        'sensitive' => true,
    ],
]; 
```

AccessControl melakukan discovery dan sync; module asal tetap menjadi owner
vocabulary dan lifecycle permission.

## Layer and Dependency Rules

- Presentation → Application → Domain ← Infrastructure.
- Domain tidak bergantung pada Laravel/Eloquent/HTTP/UI.
- Cross-module concrete dependency dilarang.
- Cross-module call memakai public contract/communication layer atau public event.
- Shared value object hanya boleh dipakai jika disepakati dan stabil.
- Setiap module memiliki communication layer sendiri.
- Dependency wajib dicatat pada `module.json`.
- Module invalid diisolasi saat runtime dan menghasilkan diagnostic.

## Module Communication

Communication layer module mencakup:

- Public contract/port.
- DTO dan mapper.
- Public domain/integration event.
- Authorization capability.
- Correlation ID propagation.
- Error/result contract.

Module lain tidak boleh mengakses private class, private model, atau private
repository secara langsung.

## Module Lifecycle

```text
Discovered → Validated → Registered → Enabled → Running
                                      ↓
                                  Disabled/Invalid
```

Lifecycle state disimpan pada registry/cache berdasarkan manifest; module
invalid tidak memblokir module valid lainnya.

## Generator Support

Generator profile `default-v1` saat ini menghasilkan:

- DDD-lite folder untuk target `AccessControl` sebagai baseline pertama, lalu
  `UserManagement` setelah public authorization contract tersedia.
- `module.json`, `module.php`, `permissions.php`.
- Service provider.
- Directory contract/application, database, test, dan frontend ownership.
- README minimum dan JSON summary.

File migration, factory, seeder, test, frontend, dan business skeleton belum
dihasilkan otomatis oleh implementasi saat ini. File tersebut dibuat pada tahap
implementasi module setelah contract disepakati.

Generator harus fail-safe, mendukung dry-run, force/yes, conflict detection,
staging promotion, dan cleanup.

## Module Testing

- Unit test domain rule/value object.
- Feature test application use case dan authorization.
- Integration test migration/repository/queue/event.
- Contract test communication layer.
- Permission discovery/sync test.
- Generated structure and manifest test.
- Browser test untuk critical module flow.

## Module Checklist

- [ ] Owner dan purpose jelas.
- [ ] `module.json` valid.
- [ ] `module.php` tidak menyimpan secret.
- [ ] `permissions.php` tersedia dan permission key unik.
- [ ] Dependency lintas module memakai contract/event.
- [ ] Migration memakai ULID dan FK/index yang benar.
- [ ] Authorization dan audit event tersedia.
- [ ] Controller middleware, policy/resource rule, dan use-case authorization
  mengikuti standard module authorization pattern.
- [ ] Frontend hanya memakai typed authorization context untuk UX dan tidak
  menjadi security boundary.
- [ ] Frontend page/component dan state loading/empty/error tersedia pada
  owner module.
- [ ] Route frontend menggunakan Ziggy dan tidak memiliki URL route tersebar.
- [ ] Responsive, keyboard, dan accessibility review tersedia.
- [ ] Test dan README tersedia.
- [ ] README internal menjelaskan contract, permission, konfigurasi, test, dan operasi.
- [ ] Module dibuat melalui generator resmi atau memiliki exception ADR.
- [ ] Discovery/registry lulus.
- [ ] Frontend component berada di owner module.
- [ ] Browser test membuktikan critical flow dari page sampai server response.
