## Purpose

Stub adalah template source code yang versioned dan deterministik. Stub tidak
berisi business logic palsu, asumsi project turunan, atau file di luar profile
generator. Module baru dibuat melalui generator resmi; pembuatan manual
membutuhkan exception ADR dan parity test dengan output generator.

## Approved Stub Categories

Profile `platform` dapat menghasilkan:

- Backend: Action, Contract, DTO, Entity, Event, Factory, Form Request, Listener,
  Migration, Model, Observer, Policy, Repository, Resource, Seeder, Service, dan Test.
- Runtime: `module.json`, `module.php`, `ServiceProvider.php`, dan `permissions.php`.
- Frontend: Index, Create, Edit, Show, Form, Table, Dialog, Drawer, Hook, Types,
  Schema, dan module `index.ts`.
- Documentation: module `README.md`; ADR draft hanya bila diminta.

CRUD, API, Livewire, GraphQL, WebSocket, dashboard, workflow, dan multi-tenancy
bukan output baseline kecuali profile dan specification baru disetujui.

## Backend Rules

| Stub | Responsibility | Boundary Rule |
|---|---|---|
| Controller | Menerima request dan memanggil action | Tidak mengakses model atau business logic langsung |
| Form Request | Validasi dan authorization input | Tidak berisi business rule |
| Resource | Transformasi response | Tidak query database |
| Action | Satu application use case | Memiliki `execute()` dan orchestration minimal |
| Service | Domain/application capability | Tidak bergantung pada HTTP atau UI |
| Contract | Public port/capability | Tidak mengekspos model atau detail infrastructure |
| Repository | Implementasi persistence contract | Tidak berisi business rule |
| DTO | Transfer data immutable | Tidak memiliki side effect |
| Entity | Domain identity dan invariant | Tidak bergantung pada Laravel/Eloquent |
| Model | Mapping persistence Eloquent | Tidak menjadi pemilik business rule |
| Policy | Authorization allow/policy rule | Tidak membuat explicit deny model |
| Event | Domain/integration notification | Typed payload dan correlation ID |
| Listener | Menangani event | Idempotent bila dapat di-retry |

Semua cross-module call menggunakan public contract, DTO, event, atau shared
value object yang telah disepakati. Direct concrete dependency lintas module
dilarang.

## Database and Test Rules

- Migration mengikuti satu perubahan per migration dan memakai index/FK sesuai desain.
- Semua primary key dan foreign key menggunakan ULID; tidak menghasilkan integer
  auto-increment atau UUID.
- Test stub mencakup unit, feature, integration, contract, dan generator output
  sesuai kebutuhan profile.
- Generated test harus membuktikan namespace, manifest, permission schema,
  forbidden dependency, dan struktur output.

## Frontend Rules

Frontend module berada di `resources/js/pages/{Domain}/{SubModule}/` dengan
`components/`, `pages/`, `schemas.ts`, `types.ts`, dan `index.ts` bila relevan.
Komponen module tidak boleh ditempatkan di shared UI. Hook menggunakan route
contract/Ziggy dan response type tervalidasi; tidak membuat endpoint string
tersebar tanpa contract.

## Permission Stub

`permissions.php` adalah identity lokal module dan memakai metadata lengkap:

```php
return [
    [
        'key' => 'user.impersonate',
        'description' => 'Impersonate an eligible user',
        'module' => 'UserManagement',
        'sensitive' => true,
    ],
];
```

`key` wajib unik secara global. AccessControl melakukan discovery dan sync,
tetapi module asal tetap menjadi owner vocabulary dan lifecycle permission.

## Header and Namespace

PHP stub wajib memakai `declare(strict_types=1);`, namespace sesuai struktur,
dan import eksplisit. TypeScript memakai strict mode, named export konsisten,
dan tidak menghasilkan Wayfinder. Namespace backend adalah:
`App\\Modules\\{Domain}\\{SubModule}`. Frontend root adalah:
`resources/js/pages/{Domain}/{SubModule}`.

## Naming and Placeholders

- Class/interface: PascalCase; interface berakhiran `Contract`.
- Service/repository/policy/request/resource: suffix sesuai jenisnya.
- Event memakai past tense; listener memakai kata kerja.

Stub placeholders:

| Placeholder | Description |
|---|---|
| `{{ namespace }}` | PHP namespace |
| `{{ module }}` | Module name |
| `{{ submodule }}` | Submodule name |
| `{{ class }}` | Class name |
| `{{ model }}` | Model name |
| `{{ table }}` | Table name |
| `{{ route }}` | Route name |
| `{{ contract }}` | Contract name |
| `{{ permission_key }}` | Permission key |
| `{{ permission_description }}` | Permission description |
| `{{ sensitive }}` | Sensitive permission flag |
| `{{ ulid }}` | ULID fixture/value |

## Generated File Acceptance

Setiap output stub wajib:

- lulus syntax check, formatter, dan static analysis;
- memiliki namespace, manifest, permission, dan path yang benar;
- memiliki test/README sesuai profile;
- menggunakan ULID dan contract-first boundary;
- tidak menghasilkan secret, credential, Wayfinder, atau Laravel Boost;
- tidak memiliki TODO ambigu atau dependency lintas module konkret.
