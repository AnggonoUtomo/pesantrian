## Test Objectives

Test harus membuktikan bahwa baseline dapat dibuat, di-discover, dijalankan,
diubah secara aman, dan diverifikasi end-to-end tanpa asumsi lisan. Fokus
baseline adalah generator, module console, AccessControl, UserManagement,
AuditLog, dan SystemSetting.

## Test Pyramid and Tools

| Level | Tool | Scope |
|---|---|---|
| Unit | Pest/PHPUnit, Vitest | Domain rule, value object, mapper, policy, hook, component |
| Feature | Pest/PHPUnit | Use case, authorization, persistence, HTTP response |
| Integration | Pest/PHPUnit | PostgreSQL, Redis, queue, event, module registry |
| Contract | Pest/PHPUnit, TypeScript typecheck | Cross-module contract, API envelope, generated manifest |
| Browser | Playwright + axe-core | Critical user journey, keyboard, accessibility |
| Static | Pint, PHPStan/Larastan, ESLint, TypeScript | Quality and type correctness |
| Security | CodeQL, OWASP Dependency-Check, manual review | Vulnerability and dependency baseline |

Browser baseline memakai Chrome, Firefox, dan WebKit pada CI. Chrome DevTools
digunakan bila investigasi membutuhkan network, console, atau performance trace.

## Coverage Threshold

| Layer | Minimum |
|---|---:|
| Domain | 90% |
| Application | 85% |
| Policy/security | 90% |
| Infrastructure | 75% |
| API/critical use case | 80% |
| Generator | 85% |
| Shared React component | 80% |
| Browser flow | Semua critical scenario, tidak memakai angka coverage |

Coverage tidak menggantikan assertion bermakna, negative path, atau security test.

## Test Environment and Data

- CI menggunakan PostgreSQL dan Redis service yang bersih.
- Test database dibuat dari migration terbaru dan diuji juga melalui upgrade path.
- Factory menghasilkan ULID valid dan data minimal yang realistis.
- Test actor mencakup anonymous, authenticated user, user dengan permission,
  auditor scoped, dan SuperSystem.
- Secret, token nyata, dan data production dilarang dalam fixture atau log.
- Browser test memakai seeded deterministic data dan tidak bergantung pada urutan
  test lain.
- Waktu dapat dikontrol untuk menguji idempotency 24 jam, audit retention, dan
  session timeout.

## Generator and Module Console Tests

Wajib menguji:

- validasi domain/module name, namespace, path, dan dependency;
- `module:inspect` membaca target valid, menolak target invalid, dan tidak
  mengubah filesystem;
- module:make menghasilkan struktur profile default-v1, manifest, README,
  permission source, route entry point, dan directory ownership;
- dry-run tidak menulis file;
- conflict tanpa force tidak mengubah target;
- mutasi tanpa force ditolak;
- CI/non-interactive membutuhkan force plus yes;
- staging failure dan promotion failure melakukan cleanup/restore;
- JSON output memiliki code stabil, data, diagnostics, dan exit code;
- module discovery, validation, serta isolated invalid module;
- output tidak mengandung Wayfinder, Laravel Boost, secret, atau dependency
  lintas module konkret.

## AccessControl Tests

- CRUD role dan permission hanya pada scope yang diizinkan.
- Permission discovery dari module-local permissions.php.
- Metadata permission wajib valid dan key global unik.
- Direct permission assignment ke user dapat diberikan dan dicabut.
- Effective authorization memakai allow permission dan policy rule.
- Tidak ada explicit deny model pada baseline.
- SuperSystem memperoleh full access melalui guard/policy khusus dan akses
  privileged tidak tampil bagi user lain.
- Authorization failure menghasilkan 403 dan tercatat bila termasuk security event.

## UserManagement and Impersonation Tests

- Create, read, update, active/inactive, soft delete, dan restore sesuai policy.
- Semua user identifier memakai ULID.
- Role assignment melalui AccessControl contract.
- Impersonation memerlukan permission user.impersonate.
- Reason wajib sebelum session dimulai.
- Target SuperSystem selalu ditolak, termasuk oleh SuperSystem.
- Session actor asli, target, start, end, reason, dan status tercatat.
- Exit impersonation eksplisit mengembalikan actor asli.
- Impersonation tidak boleh mengubah privilege actor asli secara permanen.

## AuditLog Tests

- Audit record append-only dan memiliki actor, action, subject, module,
  correlation ID, reason, dan metadata terfilter.
- Create/update/delete, authorization-sensitive action, impersonation, dan
  SystemSetting change menghasilkan audit event.
- Auditor non-SuperSystem hanya melihat scope yang diizinkan.
- SuperSystem dapat melihat seluruh audit sesuai policy.
- Actor soft delete tidak menghapus audit record.
- Secret, token, password, credential, dan sensitive payload ter-redact.
- Retention minimum satu tahun dan partition/archive trigger dapat diuji.

## SystemSetting Tests

- Hanya SuperSystem yang dapat mengubah setting.
- Global setting validasi schema, type, range, dan safe default.
- Perubahan langsung aktif setelah validation.
- Setiap perubahan mencatat reason, actor, before/after, correlation ID, dan
  result pada AuditLog.
- Rate limit per actor membaca nilai aktif dari SystemSetting.
- Idempotency menyimpan payload hash dan response selama 24 jam.
- Duplicate key dengan payload berbeda ditolak.
- Idle timeout default 30 menit dan absolute lifetime default 12 jam.
- Branding/design token mengubah runtime presentation tanpa secret plain text.
- Storage/cache failure memakai safe default dan menghasilkan diagnostic.
- `operations.rto_hours` dan `operations.rpo_hours` memiliki schema, default,
  batas aman, authorization SuperSystem, activation, dan audit test.

## API Tests

Setiap endpoint menguji:

- success envelope, pagination, sorting, filtering, dan per_page limit;
- authentication 401, authorization 403, not found 404, validation 422;
- ULID format dan invalid identifier;
- actor rate limit dan response 429;
- Idempotency-Key untuk mutation sensitif;
- duplicate request replay dan payload hash mismatch;
- correlation ID response/log propagation;
- secret redaction dan audit event.

## Frontend and Accessibility Tests

Setiap module yang memiliki alur pengguna wajib memiliki minimal satu critical
browser flow. Test harus membuktikan page dapat dibuka, permission visibility
benar, state loading/empty/error dapat ditangani, dan mutation ditolak oleh
backend saat actor tidak berwenang.

- Route Ziggy menghasilkan URL yang benar.
- Module page hanya memuat component dari owner module atau shared UI.
- Index, create, edit, show, validation, loading, empty, error, dan permission
  states diuji bila disediakan profile.
- Form keyboard navigation, focus management, label, error announcement,
  contrast, dialog escape, dan responsive layout lulus axe-core/manual review.
- Critical mobile flows mencakup login reuse, list/read, create/edit sederhana,
  action penting, impersonation indicator, dan SystemSetting guard.
- Authorization UI hanya diuji sebagai visibility/UX; setiap protected action
  juga diuji melalui server-side middleware, policy, dan use-case boundary.
- Inertia `auth.authorization` diuji typed, scoped, tidak membocorkan privileged
  permission, dan tidak dipakai sebagai pengganti backend authorization.

## Performance and Resilience Tests

- API regular endpoint P95 <= 500 ms pada baseline benchmark.
- Uji 100 concurrent users dan dataset hingga 100.000 record.
- Uji query pagination, index, N+1, Redis cache, queue retry, dan failed job.
- Uji bootstrap ketika satu module invalid; module lain tetap berjalan.
- Uji idempotent retry dan duplicate event handling.
- Uji bahwa recovery target aktif dibaca dari SystemSetting dan ditampilkan pada
  operational diagnostic.
- Tidak ada secret dalam structured log atau diagnostic output.

## Security Tests

- Authentication, session timeout, CSRF, XSS, SQL injection, mass assignment,
  authorization bypass, insecure direct object reference, dan rate-limit bypass.
- Policy matrix diuji untuk anonymous, permission user, scoped auditor, dan
  SuperSystem.
- MFA starter kit diverifikasi sebagai optional capability untuk SuperSystem.
- Dependency scan, CodeQL, dan OWASP Dependency-Check berjalan pada CI.
- Encryption-at-rest deployment setting diverifikasi pada environment target;
  field-level protection diuji untuk secret/token/credential/PII high risk.

## CI Quality Gates

Pull request wajib lulus:

1. formatting dan lint;
2. static analysis dan typecheck;
3. unit, feature, integration, contract, dan generator tests;
4. coverage threshold;
5. security/dependency scans;
6. build frontend;
7. critical Playwright and accessibility flows;
8. migration fresh-install dan upgrade verification.

Failure pada security critical/high, migration, generator, authorization, atau
critical browser flow memblokir merge. Flaky test tidak boleh diabaikan; test
harus diperbaiki atau diberi issue owner dan exception expiry.

## Release Acceptance

Release hanya diterima bila:

- seluruh requirement terkait memiliki test dan acceptance evidence;
- semua required CI gate lulus;
- tidak ada critical/high security finding terbuka;
- migration fresh dan upgrade lulus;
- generated baseline dapat direproduksi;
- documentation dan Open Decisions terkait diperbarui;
- rollback dan diagnostic command berhasil diverifikasi.
