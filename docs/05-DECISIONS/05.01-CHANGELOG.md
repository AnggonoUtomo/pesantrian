## Changelog Standard

Format mengikuti Keep a Changelog dan Semantic Versioning. Semua perubahan
yang berdampak pada developer, QA, DevOps, AI assistant, API, database,
module contract, security, deployment, atau operations wajib dicatat.

Kategori yang digunakan:

- Added: capability baru.
- Changed: perubahan behavior atau contract yang kompatibel.
- Deprecated: capability yang akan dihapus.
- Removed: capability yang dihapus.
- Fixed: bug yang diperbaiki.
- Security: perbaikan atau perubahan security.
- Documentation: perubahan dokumentasi yang relevan terhadap penggunaan.

Jangan mencatat secret, credential, payload sensitif, data user, atau detail
vulnerability yang belum boleh dipublikasikan.

## Entry Rules

Setiap release entry wajib memiliki:

- version dan tanggal release;
- ringkasan perubahan yang dapat dipahami consumer;
- affected module atau layer;
- migration/config/SystemSetting impact;
- breaking change dan action yang diperlukan;
- security/deployment/rollback note bila relevan;
- link atau reference ke issue, PR, ADR, atau release record jika tersedia.

Changelog ditulis dalam bahasa yang jelas dan berorientasi pada impact, bukan
daftar commit mentah. Commit scope tetap dapat digunakan sebagai input, tetapi
release owner wajib mengelompokkan dan merapikannya.

## Version Rules

- MAJOR untuk breaking API, database, module, contract, atau behavior.
- MINOR untuk backward-compatible feature dan module capability.
- PATCH untuk bug fix, security fix, documentation, dan maintenance.
- Pre-release memakai suffix alpha, beta, atau rc bila diperlukan.
- Version pada changelog harus sama dengan release tag dan artifact identifier.

## Unreleased

Perubahan yang sudah merge tetapi belum dirilis dicatat di sini dan dipindahkan
ke versioned entry saat release dibuat.

### Added

- Belum ada release baseline.

### Changed

- Belum ada release baseline.

### Deprecated

- Tidak ada.

### Removed

- Tidak ada.

### Fixed

- Tidak ada.

### Security

- Tidak ada.

### Documentation

- Dokumentasi baseline 00 sampai 04 sedang disusun sebagai acuan implementasi.

## Release Entry Template

Gunakan template berikut:

## [Unreleased]

### Added

- [Capability] — affected module/layer; verification reference.

### Changed

- [Behavior/contract] — migration/config/SystemSetting impact.

### Deprecated

- [Capability] — replacement and removal timeline.

### Removed

- [Capability] — migration or upgrade action.

### Fixed

- [Bug] — affected flow and regression test.

### Security

- [Security change] — public impact and deployment action.

### Documentation

- [Documentation change] — affected audience.

## Release Readiness

Sebelum memindahkan Unreleased ke versioned release:

- acceptance criteria requirement terkait lulus;
- CI, test, coverage, security, dan build gate lulus;
- migration fresh/upgrade dan rollback plan direview;
- SystemSetting changes memiliki schema, default, authorization, activation,
  dan audit evidence;
- module manifest, permission, contract, README, dan registry evidence tersedia;
- release notes mencantumkan breaking change, deployment action, dan known issue;
- release record dibuat sesuai 04.04-RELEASE.md.

## Baseline History

Belum ada release software resmi. Dokumen specification dan implementation
yang disusun sebelum release pertama tidak diberi label sebagai v1.0.0.
