## Purpose

Dokumen ini membedakan defect terverifikasi, limitation capability, risiko
implementasi, dan Open Decision. Isu tidak boleh dihapus hanya karena ada
workaround; status dan evidence harus diperbarui sampai exit criteria terpenuhi.

## Status Vocabulary

- Open: belum diselesaikan dan masih membutuhkan action.
- In Progress: action perbaikan sedang berjalan.
- Mitigated: risiko dikendalikan tetapi root cause belum dihilangkan.
- Blocked: tidak dapat dilanjutkan tanpa keputusan atau dependency eksternal.
- Resolved: fix diverifikasi dan evidence tersedia.
- Accepted Risk: owner menyetujui residual risk dengan expiry/review date.
- Won't Fix: sengaja tidak diperbaiki dengan alasan dan approval.

## Severity

| Severity | Definition | Release Impact |
|---|---|---|
| Critical | Data loss, security compromise, atau layanan utama tidak dapat digunakan | Block release |
| High | Fitur penting gagal, authorization bypass, migration/deployment risk | Block release unless approved exception |
| Medium | Dampak terbatas atau workaround tersedia | Review before release |
| Low | Cosmetic, documentation, atau improvement | Tidak otomatis block |

## Issue Record Template

Gunakan format berikut untuk issue baru:

| Field | Required Content |
|---|---|
| ID | Stable identifier, e.g. KI-007 |
| Type | Defect, limitation, risk, security, deployment, documentation |
| Title | Ringkasan singkat |
| Description | Reproduction atau context faktual |
| Severity | Critical, High, Medium, Low |
| Environment | Local, CI, staging, production |
| Affected module | Module/layer/contract yang terdampak |
| Status | Status vocabulary dokumen ini |
| Owner | Satu accountable owner |
| Evidence | Log, test, screenshot, CI run, atau incident ID |
| Workaround | Langkah aman sementara |
| Action | Perbaikan yang diperlukan |
| Target | Release/date/decision checkpoint |
| Exit criteria | Bukti bahwa issue selesai |
| Review date | Tanggal review untuk accepted risk |

## Reporting Rules

- Issue security tidak menampilkan exploit detail pada changelog atau public log.
- Issue yang memblokir release harus muncul pada release record dan approval.
- Known issue dengan workaround wajib dijelaskan pada release notes.
- Setiap issue memiliki satu owner walaupun beberapa team berkontribusi.
- Accepted Risk wajib memiliki scope, impact, mitigation, expiry/review date,
  dan approver.
- Resolved hanya boleh digunakan setelah test atau operational evidence tersedia.
- Issue terkait SystemSetting wajib mencatat key, schema/default impact,
  authorization, activation, dan audit behavior bila relevan.

## Release Gate

Release owner memeriksa:

- tidak ada Critical issue Open/In Progress/Blocked;
- tidak ada High issue tanpa mitigation dan explicit approval;
- deployment limitation cPanel/DigitalOcean sudah diverifikasi;
- backup, restore, RTO/RPO, health, queue, dan rollback evidence tersedia;
- known issue yang tersisa tercantum pada release notes;
- owner dan review date untuk accepted risk tersedia.
